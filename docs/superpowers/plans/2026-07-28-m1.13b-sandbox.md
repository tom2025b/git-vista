# M1.13b — the Git-process sandbox (#66)

**For agentic workers: REQUIRED SUB-SKILL: `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans`.**

## Goal

Ship the bounded, irreversible, *disclosed* Git-process sandbox the round-4 verdict settled on: a single pure `sandbox_argv(Policy)` chokepoint feeding one fused `gv-sandbox` shim (Landlock, then seccomp, then `execve` git), applied at every production spawn site, tiered so network operations still work, and proven by a 17-invariant escape battery that always tests the composed launcher.

## Architecture

Every production git spawn goes through one pure function, `sandbox::sandbox_argv(&Policy) -> Vec<OsString>`, which emits a launcher argv whose fixed reviewed prefix is either `bwrap …` (strict tier) or nothing (network tier) and whose tail is always `["--", "git"]`. That argv is executed by `sandbox::spawn::spawn_git_async` / `spawn_git_sync` — the only two places in the codebase that construct a `Command` from a non-literal program name — and terminates in `crates/git-vista-server/src/bin/gv-sandbox.rs`, a single fused binary that applies Landlock (ABI floor 6, fail-closed), then a terminal-action seccomp filter (AF_UNIX/io_uring/unshare/setns/seccomp denied), then `execve`s git without forking. Repository metadata is resolved and validated against the managed root *before* any policy is built, so a repository's own `.git` gitfile can never steer the grant set outside the catalog.

## Tech Stack

- Rust (stable), workspace crates `git-vista-core`, `git-vista-protocol`, `git-vista-git`, `git-vista-server`, `git-vista` (Leptos/wasm frontend).
- `tokio` 1.52.3 with the `process` feature (already present) — `tokio::process::Command`.
- **New direct dependencies of `git-vista-server`:** `libc = "0.2"` (raw Landlock syscalls, `prctl`, syscall numbers) and `seccompiler = "0.5"` (cBPF assembly with masked argument comparisons). No `landlock` crate — the raw-syscall path is ~120 lines, has no version risk around the ABI-6 structures, and lets the ABI floor be checked exactly.
- **New external runtime binary:** `bubblewrap` (`bwrap`), used only by the strict tier.
- Existing test conventions: `#[cfg(test)] mod <name>;` sibling files (pattern B, as `planner/{contract,coordination,lifecycle}_suite.rs` already do).

## Global Constraints

These apply to **every** task below. They are quoted requirements, not guidance.

1. **Landlock ABI floor is 6, not 3 and not 8.** From correction **C5** (verdict §9.2): *"Declare **ABI 6**, not 3 and not 8. ABI 8 contributes only `LANDLOCK_RESTRICT_SELF_TSYNC`, which this design does not need if the launcher is single-threaded — and it should be. […] **Fail closed** when the declared minimum is unavailable: silently applying a weaker best-effort policy is incompatible with any stated claim."* The shim is single-threaded by construction. `landlock_create_ruleset(NULL, 0, LANDLOCK_CREATE_RULESET_VERSION) < 6` ⇒ the shim exits non-zero with a named error, never a degraded policy.

2. **Test the composed launcher, never a primitive alone.** From verdict §9.4: *"The single methodological failure of round 4 was verifying layers in isolation and then crediting the composition. Every test below runs the **whole launcher**, in one configuration, against a real repository."* And §5: *"The composition rule is absolute: every invariant is verified in *one* configuration — the real production argv — never in a sub-layer."* Concretely, for every task in this plan: a test may **not** call `landlock_restrict_self`, install a seccomp filter, or exec `bwrap` directly. It must go through `sandbox_argv` + `spawn_git_{sync,async}` (for git behaviour) or `probe_argv` + the shim's `--self-probe` mode (for in-sandbox syscall behaviour). A test that constructs a primitive itself is a defect in the test, regardless of whether it passes.

3. **The shim is a single fused binary.** From verdict §7.1: *"The shim's own path **must** be inside a Landlock-granted RO tree, or `execve` of it is denied. I hit this: `ll: exec .../sc: Permission denied` (rc=105), and it silently made a benchmark look 3× *faster* than bare git. A single fused shim (Landlock + seccomp + exec in one binary) avoids the whole class."* `gv-sandbox` therefore does Landlock **and** seccomp **and** the exec of git in one process image. It must contain `.exec()` and must **not** contain `.spawn()`, `.output()`, or `.status()`. Task 15 makes that a source-level assertion.

4. **The argv tail is structurally asserted.** From **INV-16**: *"add a *structural* assertion that the produced argv **ends in `["--", "git", ...]` after a fixed reviewed prefix**. This is F7 and it is a reviewed sub-task, not a side effect."* `sandbox_argv` output must satisfy: either it is exactly `["git"]` (the `Unsandboxed` tier, reachable only through explicit persisted per-repo trust) or its last two elements are `"--"` and `"git"` and its prefix up to the first `"--"` equals a pinned reviewed constant. The probe argv (`probe_argv`) is a separate reviewed shape ending `["--self-probe"]` and never names a program at all.

5. **C1 — seccomp stacking is not monotonic.** *"A newer `SECCOMP_RET_USER_NOTIF` filter can override earlier `USER_NOTIF`/`TRACE` handling and continue a syscall. The composition therefore must use **higher-precedence terminal denials** for the boundary *and* **deny the hook the `seccomp` syscall itself**."* Every denial in this plan is `SECCOMP_RET_ERRNO` or `SECCOMP_RET_KILL_PROCESS` — never `TRACE`, never `USER_NOTIF` — and both `seccomp(2)` and `prctl(PR_SET_SECCOMP)` are denied to the child.

6. **C2 — register width.** *"Seccomp reports syscall registers *before* the kernel truncates arguments to their declared types. A socket-family comparison must mask to the effective low-width `int`, or `AF_UNIX | 0x1_0000_0000` compares unequal and passes."* Every argument comparison in the filter uses `SeccompCmpArgLen::Dword`.

7. **C3 — mount namespace and a fresh procfs are required.** *"A PID namespace does **not** update an inherited procfs mount: `/proc` keeps its mounter's PID view. Add a mount namespace with private propagation and either mount a fresh `/proc` for the child PID namespace or expose no `/proc` at all."* The strict tier's bwrap prefix therefore carries `--proc /proc` (bwrap always creates a mount namespace with private propagation).

8. **C4 — `/dev/shm`.** *"An IPC namespace isolates System V IPC and POSIX message queues but **not** pathname-based POSIX shared memory or named semaphores under `/dev/shm`. Provide a private `/dev/shm` or deny it in the filesystem policy."* The strict tier prefix carries `--tmpfs /dev/shm`; the network tier denies `/dev/shm` in the Landlock rule set.

9. **D5 is Option B and is not re-litigated.** Read-allow `$HOME`, write-deny `$HOME`, plus an explicit secret denylist (`~/.ssh`, `~/.claude`, `~/.config/gh`, `~/.aws`, `~/.netrc`, `~/.npmrc`, browser profile dirs). Landlock's most-specific-rule semantics make the denylist a `path_beneath` rule with `allowed_access = 0`.

10. **D4 is Option A and is not re-litigated.** Full tier everywhere **except** network operations. The read path pays the strict tier's ~7 ms until a profile says otherwise.

11. **D6 is Lane A's assumed default, NOT yet confirmed by Tom.** The plan assumes verdict §6 D6 **Option A**: *"`sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0` as a preflight step, failing loudly if the write fails. GitHub runners have passwordless sudo."* **This assumption has not been confirmed by Tom.** It is flagged here the same way #65's scope narrowing was flagged rather than silently assumed. Task 17 carries the note into its own commit message verbatim. If Tom chooses D6 Option B (host-gated tests, no CI validation of the bwrap-dependent invariants), only Task 17 changes; every other task is unaffected because INV-13 (Task 9) makes the capability/escape distinction explicit regardless.

12. **Subagents must not write git.** A background checkpointer owns the index. No `git add`/`commit`/`push`/`checkout`/`switch`/`reset`/`rebase`/`stash`, no branch deletion, no `./dev wip` from a subagent. Read-only git and throwaway `tempfile::TempDir` fixture repos are fine. The "commit" step written into each task below is executed by the parent session or the checkpointer, not by a task subagent.

13. **Scope deviation, flagged not silent — test-helper spawn sites are NOT migrated.** Verdict §7.1's diagram routes *"~39 test-helper sites incl. `history.rs` sync helpers"* through `spawn_git_sync`. This plan migrates **one** of them (`git_cmd.rs:385 batch_child`, because it is the witness for the process-lifetime tests and must keep mirroring the real production spawn shape) and leaves the other 37 as raw `Command::new("git")`. Two reasons, both structural: (a) `git-vista-git` is a *dependency* of `git-vista-server`, so its 8 test sites in `src/history.rs` **cannot** reach the server's sandbox module without inverting the dependency graph; (b) fixture construction is not the thing under test — the escape and compat batteries call `spawn_git_sync` directly, which is what Global Constraint 2 actually requires. If a later session wants full test-helper migration it needs a `git-vista-sandbox` crate below `git-vista-git`; that is not M1.13b.

14. **Every new dependency is a reviewed decision (F10).** *"`DEPENDENCY_EXCEPTIONS.md` does not gate new crates — Confirmed."* Task 2 adds a kernel-API dependency register and a CI step, because `libc` and `seccompiler` would otherwise sail in unreviewed.

```rust
//! M1.13b (#66): the single argv chokepoint for every git process this server
//! spawns. See `docs/superpowers/specs/2026-07-28-m1.13-round4-verdict.md`.
//!
//! Everything in this file is **pure**. No syscall, no I/O, no async. That is
//! deliberate and it is what dissolved the "do the ~39 synchronous test helpers
//! have to become async?" question (verdict §7.1): because the sandbox is
//! nothing but argv, the sync and async spawn wrappers share one policy
//! function and neither needs `block_on` or a `pre_exec` closure.

use std::ffi::OsString;
use std::path::PathBuf;

#[cfg(test)]
mod argv;

/// The strict tier's outer launcher. An external binary, deliberately: it is
/// the only thing here that creates namespaces, and `--unshare-net` is what
/// makes the strict tier incompatible with `git push` (F3).
pub(crate) const BWRAP_BIN: &str = "bwrap";

/// Overrides the shim path for tests and for a packaged install where the
/// shim does not sit beside the server binary.
pub(crate) const SHIM_BIN_ENV: &str = "GIT_VISTA_SANDBOX_BIN";

/// C5: the declared minimum Landlock ABI. Six, because ABI 6 is the first
/// with the signal and abstract-unix-socket scopes this design uses; ABI 8
/// adds only `TSYNC`, which a single-threaded launcher does not need.
pub(crate) const LANDLOCK_ABI_FLOOR: u32 = 6;

/// D5 Option B: `$HOME` is read-allowed and write-denied, and *these* are the
/// paths denied outright. Relative to `$HOME`. The list is short and auditable
/// on purpose — round 4's blanket-deny-plus-allowlist shape needed three
/// iterations to make one `git commit` work (F1, F-NEW-2) and would have kept
/// growing for every credential helper and hook interpreter.
pub(crate) const DEFAULT_SECRET_DENIES: &[&str] = &[
    ".ssh",
    ".claude",
    ".config/gh",
    ".aws",
    ".netrc",
    ".npmrc",
    ".config/google-chrome",
    ".config/chromium",
    ".mozilla",
];

/// The reviewed bwrap prefix, pinned as a constant so INV-16's structural
/// assertion has something to compare against and a drift shows up as a test
/// failure rather than as a quietly weaker sandbox.
///
/// `--proc /proc` is C3 (a pid namespace does not update an inherited procfs).
/// `--tmpfs /dev/shm` is C4 (an ipc namespace does not cover pathname-based
/// POSIX shared memory). `--die-with-parent` plus `--unshare-pid` is INV-8.
pub(crate) const STRICT_BWRAP_PREFIX: &[&str] = &[
    BWRAP_BIN,
    "--bind", "/", "/",
    "--dev-bind", "/dev", "/dev",
    "--proc", "/proc",
    "--tmpfs", "/dev/shm",
    "--unshare-pid",
    "--unshare-net",
    "--unshare-ipc",
    "--unshare-uts",
    "--unshare-cgroup",
    "--die-with-parent",
    "--new-session",
];

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum Tier {
    /// Landlock + seccomp inside a bwrap pid/net/ipc/uts/cgroup namespace.
    /// Everything except network operations (D4 Option A).
    Strict,
    /// Landlock + seccomp, no namespaces, `AF_INET`/`AF_INET6` permitted.
    /// The only tier in which `git push`/`fetch`/`clone` can work (F3).
    Network,
    /// No sandbox at all. Reachable only through explicit, persisted, per-repo
    /// operator trust, and it flies a permanent banner (INV-15).
    Unsandboxed,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub(crate) enum HookMode {
    /// Repository hooks run. They gate the operation normally (INV-11).
    Run,
    /// `core.hooksPath` is pointed at a server-owned empty directory, so no
    /// repository hook can run at all. The state the probe drops to when the
    /// host cannot provide the declared minimum (INV-13).
    Blocked { empty_dir: PathBuf },
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub(crate) struct Policy {
    pub tier: Tier,
    /// Absolute path of the fused `gv-sandbox` shim.
    pub shim: PathBuf,
    pub rw_trees: Vec<PathBuf>,
    pub ro_trees: Vec<PathBuf>,
    pub secret_denies: Vec<PathBuf>,
    pub hook_mode: HookMode,
}

/// The chokepoint. Returns the complete launcher argv **up to and including
/// the program name `git`**; the caller appends `-C <repo> <args…>`.
///
/// INV-16: the result is either exactly `["git"]` (the `Unsandboxed` tier) or
/// it ends in `["--", "git"]` after a fixed reviewed prefix.
pub(crate) fn sandbox_argv(policy: &Policy) -> Vec<OsString> {
    if policy.tier == Tier::Unsandboxed {
        return vec![OsString::from("git")];
    }
    let mut argv = shim_argv(policy);
    argv.push(OsString::from("--"));
    argv.push(OsString::from("git"));
    argv
}

/// The escape battery's launcher. Identical setup, different terminal mode:
/// the shim runs its built-in checks in-process instead of exec'ing anything.
/// That is what lets the battery satisfy the composition rule — the checks run
/// behind the very same Landlock and seccomp code path production uses —
/// without ever teaching the shim to exec an arbitrary program.
pub(crate) fn probe_argv(policy: &Policy) -> Vec<OsString> {
    let mut argv = shim_argv(policy);
    argv.push(OsString::from("--self-probe"));
    argv
}

fn shim_argv(policy: &Policy) -> Vec<OsString> {
    let mut argv: Vec<OsString> = Vec::new();
    if policy.tier == Tier::Strict {
        argv.extend(STRICT_BWRAP_PREFIX.iter().map(OsString::from));
        argv.push(OsString::from("--"));
    }
    argv.push(policy.shim.clone().into_os_string());
    argv.push(OsString::from("--abi-floor"));
    argv.push(OsString::from(LANDLOCK_ABI_FLOOR.to_string()));
    for p in &policy.rw_trees {
        argv.push(OsString::from("--rw"));
        argv.push(p.clone().into_os_string());
    }
    for p in &policy.ro_trees {
        argv.push(OsString::from("--ro"));
        argv.push(p.clone().into_os_string());
    }
    for p in &policy.secret_denies {
        argv.push(OsString::from("--deny"));
        argv.push(p.clone().into_os_string());
    }
    match &policy.hook_mode {
        HookMode::Run => argv.push(OsString::from("--hooks-run")),
        HookMode::Blocked { empty_dir } => {
            argv.push(OsString::from("--hooks-blocked"));
            argv.push(empty_dir.clone().into_os_string());
        }
    }
    argv.push(OsString::from(match policy.tier {
        Tier::Strict => "--net-deny",
        Tier::Network => "--net-allow",
        Tier::Unsandboxed => unreachable!("handled by the caller"),
    }));
    argv
}
```
