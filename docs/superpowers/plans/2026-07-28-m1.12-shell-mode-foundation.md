# M1.12 Sub-project 1 — ShellMode Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the frontend a single, Rust-owned source of truth for which of four
layout modes the window is in, and make that mode observably drive real CSS.

**Architecture:** A pure `ShellMode` enum with a `for_width(f64) -> ShellMode`
function lives in the existing `features/shell/core.rs` (host-testable, no wasm
target needed). A wasm-only `install_mode_signal()` in `features/shell/signals.rs`
watches window resize, debounces it, and updates an `RwSignal<ShellMode>`. `App`
binds that signal's CSS class onto the root `<main>` element. `styles.css` gets
four mode-scoped rule blocks, applied to the DOM that exists today.

**Tech Stack:** Rust, Leptos 0.6 (CSR), `web_sys`/`wasm_bindgen` for the resize
listener, plain CSS (no preprocessor, matches the existing stylesheet).

## Global Constraints

- No `@media` queries for layout mode — CSS keys off the mode class only. This is
  the whole reason `ShellMode` lives in Rust; a duplicated breakpoint anywhere in
  CSS defeats the point.
- `ShellMode::for_width` is a pure function — no hysteresis, no memory of a
  previous mode. Stability comes from debouncing the resize signal, not from
  sticky thresholds.
- Breakpoints, fixed: `Compact` < 600, `Portrait` 600–1023, `Wide` 1024–1439,
  `UltraWide` ≥ 1440 (all in CSS px).
- No default mode class in `index.html`. Before hydration, the bare stylesheet
  (no mode class present) must itself be a legitimate single-column layout.

## Scope note — read before starting

The approved spec (`docs/superpowers/specs/2026-07-28-m1.12-shell-mode-foundation-design.md`)
describes a three-column skeleton (left rail / center canvas / right inspector)
for `Wide`/`UltraWide`. Checked against the real codebase while writing this plan:
**there is no left rail in the DOM today** — repository/worktree selection isn't
built as a persistent panel anywhere — and the existing right-docked panel
(`.detail-panel` in `styles.css`) is `position: fixed`, not a grid column.

Building an actual left rail is real, separate UI work with no design behind it
yet — inventing one inside this plan would be scope creep past what was approved.
**This plan does not build a left rail or convert `.detail-panel` to a grid
column.** It delivers: the mode signal (fully in scope, unambiguous), and CSS mode
classes applied to what already exists — `.app`'s layout, the topbar, and
`.detail-panel`'s position/sizing per mode. A real three-column grid with a rail is
follow-up scope for whoever picks up sub-project 2 (the bottom sheet) or a
dedicated rail task — flag this to Tom rather than silently building past it.

/// Which of four layout modes the window is in, decided from width alone.
///
/// A pure function of width, never of the previous mode — that property is why
/// Rust owns this signal instead of a CSS/Rust hybrid: a breakpoint duplicated in
/// both places leaves a band of widths where the two disagree, a bug that only
/// reproduces at one exact window size. Stability under a Stage Manager drag
/// comes from debouncing the resize signal upstream (`signals::install_mode_signal`),
/// not from hysteresis here — hysteresis would make this a function of
/// `(width, previous_mode)`, so the same width could answer two different ways
/// depending on approach direction.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ShellMode {
    /// < 600px — narrow Stage Manager / split screen. One primary task visible
    /// at a time.
    Compact,
    /// 600–1023px — iPad portrait (834pt), medium split screen (507–678pt).
    Portrait,
    /// 1024–1439px — iPad landscape (1194pt).
    Wide,
    /// >= 1440px — a wide external monitor. Named for what's actually knowable:
    /// a web app can see a width, never that a display is external.
    UltraWide,
}

impl ShellMode {
    pub fn for_width(width: f64) -> Self {
        if width < 600.0 {
            Self::Compact
        } else if width < 1024.0 {
            Self::Portrait
        } else if width < 1440.0 {
            Self::Wide
        } else {
            Self::UltraWide
        }
    }

    /// The single CSS class the stylesheet keys off. No `@media` queries for
    /// mode exist anywhere in `styles.css` — this class is the only decider.
    pub fn css_class(self) -> &'static str {
        match self {
            Self::Compact => "shell-compact",
            Self::Portrait => "shell-portrait",
            Self::Wide => "shell-wide",
            Self::UltraWide => "shell-ultrawide",
        }
    }
}
```

/// Feeds a `ShellMode` signal from window width, debounced 150ms so a Stage
/// Manager drag doesn't thrash the layout on every intermediate resize event.
///
/// Debouncing here means "only the last event in a burst survives" — implemented
/// with a generation counter rather than a cancellable JS timer handle: each
/// resize bumps the counter and schedules a check; when that check's timeout
/// fires, it only applies if no later resize has bumped the counter since. A
/// stale, superseded timeout is a silent no-op rather than something that has to
/// be found and cancelled.
///
/// No hysteresis: `ShellMode::for_width` never sees the previous mode, only the
/// current width — see that function's doc comment for why.
pub fn install_mode_signal() -> RwSignal<ShellMode> {
    let mode = create_rw_signal(ShellMode::for_width(gestures::viewport_size().0));

    if let Some(win) = web_sys::window() {
        let generation = Rc::new(Cell::new(0u64));
        let cb = Closure::<dyn FnMut()>::new(move || {
            let this_generation = generation.get() + 1;
            generation.set(this_generation);
            let generation = generation.clone();
            leptos::set_timeout(
                move || {
                    if generation.get() == this_generation {
                        mode.set(ShellMode::for_width(gestures::viewport_size().0));
                    }
                },
                Duration::from_millis(150),
            );
        });
        let _ = win.add_event_listener_with_callback("resize", cb.as_ref().unchecked_ref());
        let win2 = win.clone();
        on_cleanup(move || {
            let _ = win2.remove_event_listener_with_callback("resize", cb.as_ref().unchecked_ref());
        });
    }

    mode
}
```
