# C12 — tier-dispatch design source audit

**Audit source baseline:** `603e124f4350ad13b8dafd5630998db249ffaced`. At final
verification `HEAD` was `5f18914f3b34f0dfd7325c7a199c03aacdeb788e`; the intervening
diff touched only the concurrently owned plan document, not any audited source file.
**Method:** read-only source inspection. No server was started, no port was bound, no test/build command was run, and no file other than this report was written.

## Approval answer

**Do not approve either recovered design unchanged.**

The **“already broken today” diagnosis survives**: `is_ancestor`, `git_ref_exists`, and
`rev_parse` already collapse policy construction, process-spawn, and executable failures into
ordinary factual answers (`false`/`None`). Those answers are actively wrong at several mutation
decisions; the sandbox would add another way to reach an existing defect, not invent the defect.

The stronger **“therefore this is near-zero-cost plumbing” conclusion does not survive**.
`rev_parse` alone has 20 production call occurrences with different failure semantics; two more
subprocess helpers swallow failure; Design B does not actually seal classification argv to executed
argv; clone does not fit its generic repo-policy API without a special always-untrusted pre-repo
case; and Design A's one-repository boot-totality premise is false. The corrected design can retain
the boot-gate plus request-error posture, but approval needs these gaps resolved explicitly.

## Complete caller consequences for the three swallowing helpers

### `is_ancestor` and `git_ref_exists`

Each has exactly one production call, both in the rebase live gate:

- `is_ancestor` at `crates/git-vista-server/src/handlers/rebase.rs:59` is **actively wrong**
  on failure: it advertises “not up to date” and enables the rebase action.
- `git_ref_exists` at `handlers/rebase.rs:44` is **actively wrong** on failure: it selects local
  `main`; indirect mutation and status consumers are at `handlers/rebase.rs:33-35` and `:57-59`.

### How severe is the branch-delete consequence?

The source proves loss of Git-Vista's automatic restore route: a deletion event needs `old_oid` to
produce `UndoAction::RestoreBranch` (`crates/git-vista-core/src/activity.rs:346-374`), and the
executor can journal `old_oid=None` after deleting (`crates/git-vista-server/src/planner.rs:1480-1488`).
Design A's phrase “permanently impossible” is nevertheless too absolute: source establishes loss of
the application's recorded restore point, not immediate erasure of the commit objects or every
possible external recovery path. The honest consequence is **silent loss of the supported restore
action, with possible data loss once otherwise-unreachable objects are pruned**.

## Additional swallow sites found

1. **Mutation coordinator — unknown becomes “not busy.”**
   `absolute_git_dir` turns process failure into `None` (`crates/git-vista-server/src/coordinator.rs:115-129`),
   and `refuse_if_git_busy` propagates that `None` (`coordinator.rs:103-105`). The planner treats only
   `Some(refused)` as a stop and otherwise continues (`planner.rs:229-247`). Git's own lock remains a
   later safety backstop, but the named preflight silently disappears.

2. **Planner status/freshness — unknown becomes empty generation input.**
   `worktree_status` uses `run_git(...).await.ok()?` (`planner.rs:485-492`), then
   `generation_token` uses `unwrap_or_default()` (`planner.rs:394-408`). Repeated failures can hide
   status drift. `Precondition::CleanWorktree` independently refuses `None` (`planner.rs:597-608`),
   so this is operation-dependent, not a total bypass.

Related non-subprocess repository reads have the same factual-default pattern: unreadable HEAD
becomes `None` (`planner.rs:424-430`) and ref-read/join failure becomes an empty ref set
(`planner.rs:433-446`). They are outside the requested git-process grep but reinforce that the
planner needs one explicit “unknown observation” posture rather than site-by-site defaults.

## Required design corrections before approval

1. Preserve Tom's INV-13 decision: Strict with missing bwrap/userns must refuse; no degrade path.
2. Make classification/execution identity enforceable. Returning a mutable `Command` is insufficient;
   the composition seam must own the final argv through spawn/output, or a source tripwire must forbid
   post-classification argument appends.
3. Give clone an explicit always-untrusted, pre-destination policy path rooted at the clones store.
4. Keep a boot capability gate, but construct/validate policy for the actual resolved repo at each
   operation or at every admission point, including runtime clone/rescan additions.
5. Propagate execution unavailability distinctly through all 20 `rev_parse` consumers and both extra
   swallow sites; do not merely rename `false`/`None` to another default.
6. Honor R10: delete the separate `probe_argv` route still present in this baseline
   (`crates/git-vista-server/src/sandbox/mod.rs:507-526`) and keep one composition route through
   `sandbox_argv` plus `sandbox::spawn::command_async`.

## Final decision

**The defect argument is real; the cheapness argument is not.** Approve the two-level hard-fail
direction only after the six corrections above are incorporated. Do not approve the recovered
design text as-is.
