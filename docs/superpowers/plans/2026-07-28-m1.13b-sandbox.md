## Goal

Ship the bounded, irreversible, *disclosed* Git-process sandbox the round-4 verdict settled on: a single pure `sandbox_argv(Policy)` chokepoint feeding one fused `gv-sandbox` shim (Landlock, then seccomp, then `execve` git), applied at every production spawn site, tiered so network operations still work, and proven by a 17-invariant escape battery that always tests the composed launcher.

## Architecture

Every production git spawn goes through one pure function, `sandbox::sandbox_argv(&Policy) -> Vec<OsString>`, which emits a launcher argv whose fixed reviewed prefix is either `bwrap …` (strict tier) or nothing (network tier) and whose tail is always `["--", "git"]`. That argv is executed by `sandbox::spawn`'s two command builders (`command_async` / `command_sync` as built; see the reconciliation note at the head of Task 6) — the only two places in the codebase that construct a `Command` from a non-literal program name — and terminates in `crates/git-vista-server/src/bin/gv-sandbox/main.rs`, a single fused binary that applies Landlock (ABI floor 6, fail-closed), then a terminal-action seccomp filter (AF_UNIX/io_uring/unshare/setns/seccomp denied), then `execve`s git without forking. Repository metadata is resolved and validated against the managed root *before* any policy is built, so a repository's own `.git` gitfile can never steer the grant set outside the catalog.

## Tech Stack

- Rust (stable), workspace crates `git-vista-core`, `git-vista-protocol`, `git-vista-git`, `git-vista-server`, `git-vista` (Leptos/wasm frontend).

## Global Constraints

These apply to **every** task below. They are quoted requirements, not guidance.

1. **Landlock ABI floor is 6, not 3 and not 8.** From correction **C5** (verdict §9.2): *"Declare **ABI 6**, not 3 and not 8. ABI 8 contributes only `LANDLOCK_RESTRICT_SELF_TSYNC`, which this design does not need if the launcher is single-threaded — and it should be. […] **Fail closed** when the declared minimum is unavailable: silently applying a weaker best-effort policy is incompatible with any stated claim."* The shim is single-threaded by construction. `landlock_create_ruleset(NULL, 0, LANDLOCK_CREATE_RULESET_VERSION) < 6` ⇒ the shim exits non-zero with a named error, never a degraded policy.

2. **Test the composed launcher, never a primitive alone.** From verdict §9.4: *"The single methodological failure of round 4 was verifying layers in isolation and then crediting the composition. Every test below runs the **whole launcher**, in one configuration, against a real repository."* And §5: *"The composition rule is absolute: every invariant is verified in *one* configuration — the real production argv — never in a sub-layer."* Concretely, for every task in this plan: a test may **not** call `landlock_restrict_self`, install a seccomp filter, or exec `bwrap` directly. A test that constructs a primitive itself is a defect in the test, regardless of whether it passes.

    > **Amended 2026-07-29 (Tom's decision, audit C11 + the anti-vacuity contract): there is exactly ONE sanctioned composition route, not two.** This constraint previously named a second route — `probe_argv` plus the shim's `--self-probe` mode. **That route has never existed.** `probe_argv` emits `--self-probe`, but the shim's argv parser has no such arm and rejects unknown flags; grepping the shim source for `self-probe` returns zero hits. The route was a self-authored requirement satisfied by nothing, and building the full JSON `ProbeReport` feature purely to make the constraint true would have been present complexity bought with no reduction in future pain. So `probe_argv` and its two tests are **deleted** (see the ordered work in the C11 remediation), and the sanctioned route is now singular:
    >
    > **Every test drives `sandbox_argv` + `sandbox::spawn::command_async`.** Not `command_sync`, and never the test-only `shim_cli::launch`, which reimplements command construction and — measured — diverges from production in a security-relevant direction: it does `.env_clear()` down to `PATH`/`HOME` while production deliberately inherits the server's whole environment. A harness strictly *more* hardened than production is the wrong direction for a security battery, and it is how five tests came to prove shim containment while crediting production composition with it.

3. **The shim is a single fused binary.** From verdict §7.1: *"The shim's own path **must** be inside a Landlock-granted RO tree, or `execve` of it is denied. I hit this: `ll: exec .../sc: Permission denied` (rc=105), and it silently made a benchmark look 3× *faster* than bare git. A single fused shim (Landlock + seccomp + exec in one binary) avoids the whole class."* `gv-sandbox` therefore does Landlock **and** seccomp **and** the exec of git in one process image. It must contain `.exec()` and must **not** contain `.spawn()`, `.output()`, or `.status()`. Task 15 makes that a source-level assertion.

4. **The argv tail is structurally asserted.** From **INV-16**: *"add a *structural* assertion that the produced argv **ends in `["--", "git", ...]` after a fixed reviewed prefix**. This is F7 and it is a reviewed sub-task, not a side effect."* `sandbox_argv` output must satisfy: either it is exactly `["git"]` (the `Unsandboxed` tier, reachable only through explicit persisted per-repo trust) or its last two elements are `"--"` and `"git"` and its prefix up to the first `"--"` equals a pinned reviewed constant.

5. **C1 — seccomp stacking is not monotonic.** *"A newer `SECCOMP_RET_USER_NOTIF` filter can override earlier `USER_NOTIF`/`TRACE` handling and continue a syscall. The composition therefore must use **higher-precedence terminal denials** for the boundary *and* **deny the hook the `seccomp` syscall itself**."* Every denial in this plan is `SECCOMP_RET_ERRNO` or `SECCOMP_RET_KILL_PROCESS` — never `TRACE`, never `USER_NOTIF` — and both `seccomp(2)` and `prctl(PR_SET_SECCOMP)` are denied to the child.

6. **C2 — register width.** *"Seccomp reports syscall registers *before* the kernel truncates arguments to their declared types. A socket-family comparison must mask to the effective low-width `int`, or `AF_UNIX | 0x1_0000_0000` compares unequal and passes."* Every argument comparison in the filter uses `SeccompCmpArgLen::Dword`.

7. **C3 — mount namespace and a fresh procfs are required.** *"A PID namespace does **not** update an inherited procfs mount: `/proc` keeps its mounter's PID view. Add a mount namespace with private propagation and either mount a fresh `/proc` for the child PID namespace or expose no `/proc` at all."* The strict tier's bwrap prefix therefore carries `--proc /proc` (bwrap always creates a mount namespace with private propagation).

8. **C4 — `/dev/shm`.** *"An IPC namespace isolates System V IPC and POSIX message queues but **not** pathname-based POSIX shared memory or named semaphores under `/dev/shm`. Provide a private `/dev/shm` or deny it in the filesystem policy."* The strict tier prefix carries `--tmpfs /dev/shm`; the network tier denies `/dev/shm` in the Landlock rule set.

9. **D5 is Option B and is not re-litigated.** Read-allow `$HOME`, write-deny `$HOME`, plus an explicit secret exclusion set (`~/.ssh`, `~/.claude`, `~/.config/gh`, `~/.aws`, `~/.netrc`, `~/.npmrc`, browser profile dirs). **Not** a `path_beneath` deny rule — measured rejected by the kernel (`ENOMSG`) and, even where accepted, inert against an ancestor grant. Enforced instead by enumerate-and-skip: the shim grants a tree's entries one rule at a time, skipping anything in the exclusion set (see `DEFAULT_SECRET_EXCLUDES` in `sandbox/mod.rs`).

10. **D4 is Option A and is not re-litigated.** Full tier everywhere **except** network operations. The read path pays the strict tier's ~7 ms until a profile says otherwise.

11. **D6 is Option A — confirmed by Tom, 2026-07-29.** Verdict §6 D6 **Option A**: *"`sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0` as a preflight step, failing loudly if the write fails. GitHub runners have passwordless sudo."* Decision recorded in `design-docs/2026-07-29-d6-sandbox-ci-preflight-decision.md`. Task 17 implements 17.1's preflight step as already spec'd; no other task is affected by this confirmation.

12. **Subagents must not write git.** A background checkpointer owns the index. No `git add`/`commit`/`push`/`checkout`/`switch`/`reset`/`rebase`/`stash`, no branch deletion, no `./dev wip` from a subagent. Read-only git and throwaway `tempfile::TempDir` fixture repos are fine. The "commit" step written into each task below is executed by the parent session or the checkpointer, not by a task subagent.

13. **Scope deviation, flagged not silent — test-helper spawn sites are NOT migrated.** Verdict §7.1's diagram routes *"~39 test-helper sites incl. `history.rs` sync helpers"* through `spawn_git_sync`. This plan migrates **one** of them (`git_cmd.rs:385 batch_child`, because it is the witness for the process-lifetime tests and must keep mirroring the real production spawn shape) and leaves the other 37 as raw `Command::new("git")`. Two reasons, both structural: (a) `git-vista-git` is a *dependency* of `git-vista-server`, so its 8 test sites in `src/history.rs` **cannot** reach the server's sandbox module without inverting the dependency graph; (b) fixture construction is not the thing under test — the escape and compat batteries call `spawn_git_sync` directly, which is what Global Constraint 2 actually requires. If a later session wants full test-helper migration it needs a `git-vista-sandbox` crate below `git-vista-git`; that is not M1.13b.

14. **Every new dependency is a reviewed decision (F10).** *"`DEPENDENCY_EXCEPTIONS.md` does not gate new crates — Confirmed."* Task 2 adds a kernel-API dependency register and a CI step, because `libc` and `seccompiler` would otherwise sail in unreviewed.

15. **INV-13 resolved — a host that cannot supply the Strict tier HARD-FAILS the operation. Decided by Tom, 2026-07-29.** When `Tier::Strict` is selected and `bwrap` or unprivileged user namespaces are unavailable, `policy_for_repo` returns an error and the git operation refuses to run. It does **not** degrade to `Tier::Network`, and it does not degrade-and-block-hooks. This is Global Constraint 1 (C5) applied one level up: *"silently applying a weaker best-effort policy is incompatible with any stated claim."* A degrade would hand local **read** operations outbound TCP on the git ports — precisely the best-effort downgrade C5 forbids — and it would do so on the path a user exercises constantly.

    The accepted cost is stated plainly rather than buried: **git-vista is unusable on a host without bubblewrap.** That is the intended trade. Prefer an app that refuses to run over one that runs less-sandboxed than it claims.

    This choice also happens to need **no new type machinery**, which is why it survives the Future Me Check as well as the security argument. `Policy` deliberately cannot represent "Strict without bwrap" — `shim_argv` panics on that state (`sandbox/mod.rs`) — so hard-failing is expressible as an ordinary `Err` from the policy builder. Every degrade option would first have required inventing a representable "Strict that is not Strict", i.e. adding a type to describe a weaker guarantee. Fail-closed is simultaneously the strictest and the simplest option.

    Note what this does **not** change: `HookMode::Blocked` still exists and is still correct for its own case (an operator-trusted `Unsandboxed` repository where hooks must nonetheless not run). It is simply not INV-13's answer.

```rust
//! M1.13b (#66): the single argv chokepoint for every git process this server
//! spawns. See `docs/superpowers/specs/2026-07-28-m1.13-round4-verdict.md`.
//!
//! Everything in this file is **pure**. No syscall, no I/O, no async. That is
//! deliberate and it is what dissolved the "do the ~39 synchronous test helpers
//! have to become async?" question (verdict §7.1): because the sandbox is
//! nothing but argv, the sync and async spawn wrappers share one policy
//! function and neither needs `block_on` or a `pre_exec` closure.

use std::ffi::OsString;
use std::path::{Path, PathBuf};

#[cfg(test)]
mod argv;

/// Absolute paths the strict tier's outer launcher is looked for at, in
/// order. Never a bare `"bwrap"` name — `execvp` would resolve that against
/// the inherited `PATH`, which is exactly the substitution hole a namespace
/// boundary must not have. Resolved once via `bwrap::bwrap_path()`.
pub(crate) const BWRAP_CANDIDATES: &[&str] = &["/usr/bin/bwrap", "/bin/bwrap", "/usr/local/bin/bwrap"];

/// Overrides the shim path for tests and for a packaged install where the
/// shim does not sit beside the server binary.
pub(crate) const SHIM_BIN_ENV: &str = "GIT_VISTA_SANDBOX_BIN";

/// C5: the declared minimum Landlock ABI. Six, because ABI 6 is the first
/// with the signal and abstract-unix-socket scopes this design uses; ABI 8
/// adds only `TSYNC`, which a single-threaded launcher does not need.
pub(crate) const LANDLOCK_ABI_FLOOR: u32 = 6;

/// D5 Option B: `$HOME` is read-allowed and write-denied, and *these* are the
/// paths denied outright. Relative to `$HOME`. The list is short and auditable
/// on purpose — round 4's blanket-deny-plus-allowlist shape needed three
/// iterations to make one `git commit` work (F1, F-NEW-2) and would have kept
/// growing for every credential helper and hook interpreter.
pub(crate) const DEFAULT_SECRET_EXCLUDES: &[&str] = &[
    ".ssh",
    ".claude",
    ".claude.json",
    ".config/gh",
    ".aws",
    ".netrc",
    ".git-credentials",
    ".npmrc",
    ".gnupg",
    ".docker",
    ".kube",
    ".config/google-chrome",
    ".config/chromium",
    ".mozilla",
];

/// `DEFAULT_SECRET_EXCLUDES` is relative to `$HOME`; every `Policy` field is
/// absolute. Every policy builder must go through this rather than joining
/// the constant by hand — see Task 6/7/9's builder consolidation.
pub(crate) fn secret_excludes_for_home(home: &Path) -> Vec<PathBuf> {
    DEFAULT_SECRET_EXCLUDES.iter().map(|s| home.join(s)).collect()
}

/// The TCP ports the network tier may `connect()` to (Landlock's
/// `landlock_net_port_attr` has no address field, so this constrains ports,
/// never hosts — see ADR 0028, decision A).
pub(crate) const DEFAULT_GIT_PORTS: &[u16] = &[22, 443, 80, 9418];

/// The reviewed bwrap **arguments**, pinned as a constant so INV-16's
/// structural assertion has something to compare against and a drift shows up
/// as a test failure rather than as a quietly weaker sandbox. The launcher's
/// own path is deliberately *not* in here — it lives in `Policy::bwrap`,
/// resolved per host from `BWRAP_CANDIDATES`, so this constant stays fixed.
///
/// `--proc /proc` is C3 (a pid namespace does not update an inherited procfs).
/// `--tmpfs /dev/shm` is C4 (an ipc namespace does not cover pathname-based
/// POSIX shared memory). `--die-with-parent` plus `--unshare-pid` is INV-8.
pub(crate) const STRICT_BWRAP_ARGS: &[&str] = &[
    "--bind", "/", "/",
    "--dev-bind", "/dev", "/dev",
    "--proc", "/proc",
    "--tmpfs", "/dev/shm",
    "--unshare-pid",
    "--unshare-net",
    "--unshare-ipc",
    "--unshare-uts",
    "--unshare-cgroup",
    "--die-with-parent",
    "--new-session",
];

/// Resolving the strict tier's `bwrap` launcher, once, to an absolute path.
/// The one impure corner of `sandbox`: it stats the filesystem.
pub(crate) mod bwrap {
    use super::BWRAP_CANDIDATES;
    use std::path::{Path, PathBuf};
    use std::sync::OnceLock;

    static RESOLVED: OnceLock<Option<PathBuf>> = OnceLock::new();

    /// `None` if bwrap is not at any of the reviewed locations — a host in
    /// that state cannot build a `Strict` policy and must degrade (INV-13).
    pub(crate) fn bwrap_path() -> Option<&'static Path> {
        RESOLVED.get_or_init(|| resolve(BWRAP_CANDIDATES)).as_deref()
    }

    fn resolve(candidates: &[&str]) -> Option<PathBuf> {
        candidates.iter().map(PathBuf::from).find(|p| p.is_file())
    }
}

/// Locating the `gv-sandbox` shim, once, and refusing to guess. The second
/// impure corner of `sandbox` (see `bwrap` for the first).
pub(crate) mod shim {
    use super::SHIM_BIN_ENV;
    use std::path::{Path, PathBuf};
    use std::sync::OnceLock;

    /// Why a shim path could not be produced. A named error rather than a
    /// panic: policy construction runs per operation, and a worker dying
    /// because the binary moved is worse than an operation reporting the
    /// host cannot supply the sandbox (INV-13).
    #[derive(Debug, Clone, PartialEq, Eq)]
    pub(crate) enum ShimError {
        BadOverride { value: PathBuf, why: &'static str },
        NotFound { looked_in: PathBuf },
        NoCurrentExe,
        /// `$HOME` is unset, so a policy cannot say which tree to grant or
        /// which secrets to withhold. Building a policy without it would grant
        /// nothing and silently break git identity, so it is a hard error
        /// instead. Constructed by `policy_for_repo` (Task 6), not here.
        NoHome,
    }

    static RESOLVED: OnceLock<Result<PathBuf, ShimError>> = OnceLock::new();

    /// Deliberately never a `PATH` lookup and never a fallback to a bare
    /// `"gv-sandbox"` name — that would reopen the exact substitution hole
    /// `BWRAP_CANDIDATES` closes for bwrap. Not found ⇒ a named error, never
    /// a silently-PATH-resolved guess.
    pub(crate) fn shim_path() -> Result<&'static Path, &'static ShimError> {
        match RESOLVED.get_or_init(resolve) {
            Ok(p) => Ok(p.as_path()),
            Err(e) => Err(e),
        }
    }

    fn resolve() -> Result<PathBuf, ShimError> {
        if let Some(raw) = std::env::var_os(SHIM_BIN_ENV) {
            let p = PathBuf::from(&raw);
            if !p.is_absolute() || !p.is_file() {
                return Err(ShimError::BadOverride { value: p, why: "must be an absolute path to an existing file" });
            }
            return Ok(p);
        }
        let exe = std::env::current_exe().map_err(|_| ShimError::NoCurrentExe)?;
        let mut dir = exe.parent().ok_or(ShimError::NoCurrentExe)?.to_path_buf();
        // Under `cargo test` the running binary is `target/<profile>/deps/<name>-<hash>`,
        // so the sibling lookup must step *out* of `deps` first, or it resolves
        // to `target/<profile>/deps/gv-sandbox`, which does not exist.
        if dir.file_name().is_some_and(|n| n == "deps") {
            dir = dir.parent().map(Path::to_path_buf).unwrap_or(dir);
        }
        let candidate = dir.join("gv-sandbox");
        if candidate.is_file() {
            Ok(candidate)
        } else {
            Err(ShimError::NotFound { looked_in: dir })
        }
    }
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum Tier {
    /// Landlock + seccomp inside a bwrap pid/net/ipc/uts/cgroup namespace.
    /// Everything except network operations (D4 Option A).
    Strict,
    /// Landlock + seccomp, no namespaces, `AF_INET`/`AF_INET6` permitted.
    /// The only tier in which `git push`/`fetch`/`clone` can work (F3).
    Network,
    /// No sandbox at all. Reachable only through explicit, persisted, per-repo
    /// operator trust, and it flies a permanent banner (INV-15).
    Unsandboxed,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub(crate) enum HookMode {
    /// Repository hooks run. They gate the operation normally (INV-11).
    Run,
    /// `core.hooksPath` is pointed at a server-owned empty directory, so no
    /// repository hook can run at all. The state the probe drops to when the
    /// host cannot provide the declared minimum (INV-13).
    Blocked { empty_dir: PathBuf },
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub(crate) struct Policy {
    pub tier: Tier,
    /// Absolute path of the fused `gv-sandbox` shim.
    pub shim: PathBuf,
    /// Absolute path of the strict tier's `bwrap` launcher, resolved once via
    /// `bwrap::bwrap_path()` — never from `PATH`. `None` in every tier that
    /// does not launch it; a `Strict` policy without it must degrade loudly
    /// (INV-13) rather than run with no namespaces.
    pub bwrap: Option<PathBuf>,
    pub rw_trees: Vec<PathBuf>,
    pub ro_trees: Vec<PathBuf>,
    /// Absolute paths withheld from the grants above by enumerate-and-skip.
    /// See `DEFAULT_SECRET_EXCLUDES` — this is not a Landlock deny rule.
    pub secret_excludes: Vec<PathBuf>,
    /// TCP ports the network tier may `connect()` to. Empty in every other
    /// tier.
    pub net_ports: Vec<u16>,
    pub hook_mode: HookMode,
}

/// The chokepoint. Returns the complete launcher argv **up to and including
/// the program name `git`**; the caller appends `-C <repo> <args…>`.
///
/// INV-16: three shapes, not two (row 25). `Unsandboxed` with hooks running is
/// exactly `["git"]`; `Unsandboxed` with hooks blocked is `["git", "-c",
/// "core.hooksPath=<empty_dir>"]` — no sandbox does not mean hooks cannot be
/// suppressed. Every other tier ends in `["--", "git"]` after a fixed
/// reviewed prefix.
pub(crate) fn sandbox_argv(policy: &Policy) -> Vec<OsString> {
    if policy.tier == Tier::Unsandboxed {
        let mut argv = vec![OsString::from("git")];
        if let HookMode::Blocked { empty_dir } = &policy.hook_mode {
            argv.push(OsString::from("-c"));
            argv.push(OsString::from(format!("core.hooksPath={}", empty_dir.display())));
        }
        return argv;
    }
    let mut argv = shim_argv(policy);
    argv.push(OsString::from("--"));
    argv.push(OsString::from("git"));
    argv
}

fn shim_argv(policy: &Policy) -> Vec<OsString> {
    let mut argv: Vec<OsString> = Vec::new();
    if policy.tier == Tier::Strict {
        let bwrap = policy.bwrap.as_ref().expect("strict policy must resolve bwrap or fail to build");
        argv.push(bwrap.clone().into_os_string());
        argv.extend(STRICT_BWRAP_ARGS.iter().map(OsString::from));
        argv.push(OsString::from("--"));
    }
    argv.push(policy.shim.clone().into_os_string());
    argv.push(OsString::from("--abi-floor"));
    argv.push(OsString::from(LANDLOCK_ABI_FLOOR.to_string()));
    for p in &policy.rw_trees {
        argv.push(OsString::from("--rw"));
        argv.push(p.clone().into_os_string());
    }
    for p in &policy.ro_trees {
        argv.push(OsString::from("--ro"));
        argv.push(p.clone().into_os_string());
    }
    for p in &policy.secret_excludes {
        argv.push(OsString::from("--exclude"));
        argv.push(p.clone().into_os_string());
    }
    match &policy.hook_mode {
        HookMode::Run => argv.push(OsString::from("--hooks-run")),
        HookMode::Blocked { empty_dir } => {
            argv.push(OsString::from("--hooks-blocked"));
            argv.push(empty_dir.clone().into_os_string());
        }
    }
    argv.push(OsString::from(match policy.tier {
        Tier::Strict => "--net-deny",
        Tier::Network => "--net-allow",
        Tier::Unsandboxed => unreachable!("handled by the caller"),
    }));
    if policy.tier == Tier::Network {
        for port in &policy.net_ports {
            argv.push(OsString::from("--net-port"));
            argv.push(OsString::from(port.to_string()));
        }
    }
    argv
}

//! M1.13b (#66): the fused sandbox shim.
//!
//! **Fused on purpose.** Round 4 ran Landlock and seccomp as two separate
//! helper binaries and hit `exec .../sc: Permission denied` (rc=105) — the
//! second helper's own path was not inside a Landlock-granted tree — which
//! silently made a benchmark look 3x *faster* than bare git. One process image
//! that restricts itself and then `execve`s git cannot have that bug.
//!
//! Order is load-bearing and is the reverse of how it reads:
//!   1. close every inherited descriptor above 2      (INV-7)
//!   2. `prctl(PR_SET_NO_NEW_PRIVS, 1)`               (required by both layers)
//!   3. Landlock: check the ABI floor, build, restrict_self   (INV-1..3)
//!   4. seccomp: assemble terminal-action cBPF, apply (INV-4..6, C1, C2)
//!   5. `execve` git — never fork, never spawn        (fused-binary rule)
//!
//! This binary never execs anything but `git`; `-- git …` is its only
//! terminal mode.

use std::ffi::OsString;
use std::path::PathBuf;

mod landlock;
mod seccomp_filter;

const EXIT_ARGV: i32 = 90;
const EXIT_ABI: i32 = 91;
const EXIT_LANDLOCK: i32 = 92;
const EXIT_SECCOMP: i32 = 93;
const EXIT_EXEC: i32 = 94;

#[derive(Debug)]
struct Args {
    abi_floor: u32,
    rw: Vec<PathBuf>,
    ro: Vec<PathBuf>,
    /// D5 Option B: paths withheld from the grants above by enumerate-and-skip
    /// (never a Landlock deny rule -- see `landlock::restrict`'s doc comment).
    exclude: Vec<PathBuf>,
    hooks_blocked_dir: Option<PathBuf>,
    net_allow: bool,
    /// Always `Some` by the time `main` reads it: `parse`'s only terminal
    /// branches are `--` (which sets this) and the fallthrough `die` (which
    /// never returns), so `None` here is unreachable, not a second mode.
    git_args: Option<Vec<OsString>>,
}

fn die(code: i32, msg: &str) -> ! {
    eprintln!("gv-sandbox: {msg}");
    std::process::exit(code)
}

fn parse(mut it: impl Iterator<Item = OsString>) -> Args {
    let mut a = Args {
        abi_floor: 6,
        rw: Vec::new(),
        ro: Vec::new(),
        exclude: Vec::new(),
        hooks_blocked_dir: None,
        net_allow: false,
        git_args: None,
    };
    let mut saw_net = false;
    let mut saw_hooks = false;
    while let Some(arg) = it.next() {
        let s = arg.to_string_lossy().into_owned();
        let mut want = |name: &str| -> OsString {
            it.next().unwrap_or_else(|| die(EXIT_ARGV, &format!("{name} needs a value")))
        };
        match s.as_str() {
            "--abi-floor" => {
                a.abi_floor = want("--abi-floor")
                    .to_string_lossy()
                    .parse()
                    .unwrap_or_else(|_| die(EXIT_ARGV, "--abi-floor is not a number"));
            }
            "--rw" => a.rw.push(PathBuf::from(want("--rw"))),
            "--ro" => a.ro.push(PathBuf::from(want("--ro"))),
            "--exclude" => a.exclude.push(PathBuf::from(want("--exclude"))),
            "--hooks-run" => saw_hooks = true,
            "--hooks-blocked" => {
                saw_hooks = true;
                a.hooks_blocked_dir = Some(PathBuf::from(want("--hooks-blocked")));
            }
            "--net-deny" => { saw_net = true; a.net_allow = false; }
            "--net-allow" => { saw_net = true; a.net_allow = true; }
            "--" => {
                let program = it.next().unwrap_or_else(|| die(EXIT_ARGV, "`--` with no program"));
                if program != OsString::from("git") {
                    die(EXIT_ARGV, "this shim execs only `git`; nothing else is reachable through it");
                }
                a.git_args = Some(it.collect());
                return finish(a, saw_hooks, saw_net, true);
            }
            other => die(EXIT_ARGV, &format!("unknown argument `{other}`")),
        }
    }
    die(EXIT_ARGV, "no terminal mode: expected `-- git …`")
}

fn finish(a: Args, saw_hooks: bool, saw_net: bool, saw_terminal: bool) -> Args {
    if !saw_hooks { die(EXIT_ARGV, "a hook mode is mandatory: --hooks-run or --hooks-blocked <dir>"); }
    if !saw_net { die(EXIT_ARGV, "a network mode is mandatory: --net-deny or --net-allow"); }
    if !saw_terminal { die(EXIT_ARGV, "no terminal mode"); }
    a
}

/// INV-7 / A7: rights on an already-open descriptor are fixed at open time and
/// survive `restrict_self`, so a descriptor the supervisor forgot to mark
/// `O_CLOEXEC` is a hole Landlock cannot close. Rust opens with `O_CLOEXEC` by
/// default, but "by default" is not an invariant — this closes them anyway, and
/// `escape_suite::no_leaked_fd` asserts the result from inside.
fn close_inherited_descriptors() {
    let Ok(entries) = std::fs::read_dir("/proc/self/fd") else {
        // No procfs (a `--proc`-less namespace): fall back to a bounded sweep.
        for fd in 3..1024 {
            unsafe { libc::close(fd) };
        }
        return;
    };
    let fds: Vec<i32> = entries
        .filter_map(|e| e.ok())
        .filter_map(|e| e.file_name().to_string_lossy().parse::<i32>().ok())
        .filter(|fd| *fd > 2)
        .collect();
    for fd in fds {
        unsafe { libc::close(fd) };
    }
}

fn main() {
    let args = parse(std::env::args_os().skip(1));
    close_inherited_descriptors();

    if unsafe { libc::prctl(libc::PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0) } != 0 {
        die(EXIT_LANDLOCK, "PR_SET_NO_NEW_PRIVS failed");
    }

    let abi = landlock::abi_version().unwrap_or(0);
    if abi < args.abi_floor {
        die(EXIT_ABI, &format!(
            "Landlock ABI {abi} is below the declared floor {} — refusing to run with a weaker \
             policy (C5: fail closed, never best-effort)", args.abi_floor));
    }
    if let Err(e) = landlock::restrict(&args.rw, &args.ro, &args.exclude) {
        die(EXIT_LANDLOCK, &format!("Landlock setup failed: {e}"));
    }
    if let Err(e) = seccomp_filter::apply(args.net_allow) {
        die(EXIT_SECCOMP, &format!("seccomp setup failed: {e}"));
    }

    let git_args = args.git_args.expect(
        "parse() never returns with git_args unset: the only terminal branches \
         are `--` (which sets it) and the fallthrough `die`, which does not return",
    );
    if let Some(dir) = &args.hooks_blocked_dir {
        std::env::set_var("GIT_CONFIG_COUNT", "1");
        std::env::set_var("GIT_CONFIG_KEY_0", "core.hooksPath");
        std::env::set_var("GIT_CONFIG_VALUE_0", dir);
    }
    let err = exec_git(&git_args);
    die(EXIT_EXEC, &format!("execve git failed: {err}"));
}

/// The fused exec. `CommandExt::exec` replaces this process image — it does not
/// fork, does not spawn, and never returns on success. That is the whole point
/// of the fused-binary rule, and `argv_boundary` asserts textually that this
/// file contains `.exec()` and none of `.spawn()`/`.output()`/`.status()`.
fn exec_git(args: &[OsString]) -> std::io::Error {
    use std::os::unix::process::CommandExt;
    std::process::Command::new("git").args(args).exec()
}

```rust
//! Raw Landlock syscalls. No wrapper crate on purpose (see
//! docs/NATIVE_DEPENDENCIES.md): the ABI-6 attribute layout and the exact
//! floor check are the security-relevant surface, and a crate that silently
//! negotiates a weaker ABI is precisely what C5 forbids.

use std::os::unix::io::AsRawFd;
use std::path::Path;

const SYS_CREATE_RULESET: libc::c_long = 444;
const SYS_ADD_RULE: libc::c_long = 445;
const SYS_RESTRICT_SELF: libc::c_long = 446;

const CREATE_RULESET_VERSION: u32 = 1 << 0;
const RULE_PATH_BENEATH: u32 = 1;

// The ABI-6 filesystem access set, bit for bit.
const FS_EXECUTE: u64 = 1 << 0;
const FS_WRITE_FILE: u64 = 1 << 1;
const FS_READ_FILE: u64 = 1 << 2;
const FS_READ_DIR: u64 = 1 << 3;
const FS_REMOVE_DIR: u64 = 1 << 4;
const FS_REMOVE_FILE: u64 = 1 << 5;
const FS_MAKE_CHAR: u64 = 1 << 6;
const FS_MAKE_DIR: u64 = 1 << 7;
const FS_MAKE_REG: u64 = 1 << 8;
const FS_MAKE_SOCK: u64 = 1 << 9;
const FS_MAKE_FIFO: u64 = 1 << 10;
const FS_MAKE_BLOCK: u64 = 1 << 11;
const FS_MAKE_SYM: u64 = 1 << 12;
const FS_REFER: u64 = 1 << 13;
const FS_TRUNCATE: u64 = 1 << 14;
const FS_IOCTL_DEV: u64 = 1 << 15;

const FS_ALL: u64 = FS_EXECUTE | FS_WRITE_FILE | FS_READ_FILE | FS_READ_DIR
    | FS_REMOVE_DIR | FS_REMOVE_FILE | FS_MAKE_CHAR | FS_MAKE_DIR | FS_MAKE_REG
    | FS_MAKE_SOCK | FS_MAKE_FIFO | FS_MAKE_BLOCK | FS_MAKE_SYM | FS_REFER
    | FS_TRUNCATE | FS_IOCTL_DEV;

/// Read-only means read, list, and execute — and nothing that mutates. D5
/// Option B's "read-allow $HOME" is exactly this set applied to `$HOME`.
const FS_RO: u64 = FS_EXECUTE | FS_READ_FILE | FS_READ_DIR;

const NET_BIND_TCP: u64 = 1 << 0;
const NET_CONNECT_TCP: u64 = 1 << 1;

/// ABI 6 scopes. `ABSTRACT_UNIX_SOCKET` is why the floor is 6 and not 3.
/// It closes abstract-namespace unix sockets at the Landlock layer; pathname
/// sockets (`/run/docker.sock`) are **not** covered until ABI 9's
/// `LANDLOCK_ACCESS_FS_RESOLVE_UNIX`, which is why seccomp is mandatory and
/// not belt-and-braces (verdict §9.1).
const SCOPE_ABSTRACT_UNIX_SOCKET: u64 = 1 << 0;
const SCOPE_SIGNAL: u64 = 1 << 1;

#[repr(C)]
struct RulesetAttr {
    handled_access_fs: u64,
    handled_access_net: u64,
    scoped: u64,
}

/// `struct landlock_path_beneath_attr` is `__attribute__((packed))` in the
/// UAPI. Getting this wrong yields EINVAL at best and a silently wrong rule at
/// worst, so the packing is not optional.
#[repr(C, packed)]
struct PathBeneathAttr {
    allowed_access: u64,
    parent_fd: i32,
}

pub fn abi_version() -> Option<u32> {
    let rc = unsafe {
        libc::syscall(SYS_CREATE_RULESET, std::ptr::null::<RulesetAttr>(), 0usize, CREATE_RULESET_VERSION)
    };
    (rc > 0).then(|| rc as u32)
}

fn add_path_rule(ruleset: i32, path: &Path, access: u64) -> std::io::Result<bool> {
    let file = match std::fs::File::open(path) {
        Ok(f) => f,
        // A path that does not exist cannot be granted or denied. Report it so
        // the caller can log it; it is never an error, because `~/.aws` not
        // existing is the common case and must not fail the launch.
        Err(_) => return Ok(false),
    };
    let attr = PathBeneathAttr { allowed_access: access, parent_fd: file.as_raw_fd() };
    let rc = unsafe {
        libc::syscall(SYS_ADD_RULE, ruleset, RULE_PATH_BENEATH, &attr as *const _, 0usize)
    };
    if rc != 0 {
        return Err(std::io::Error::last_os_error());
    }
    Ok(true)
}

/// Landlock is deny-by-default and has no working "deny" rule. Measured on
/// this host (kernel Landlock ABI 8, first-party C probe, both rule orders): a
/// `path_beneath` rule with `allowed_access = 0` is rejected by the kernel
/// (`landlock_add_rule` -> `rc=-1, errno=42 (ENOMSG)`), and even where a
/// nested lower-privilege rule *is* accepted, it does not revoke a broader
/// ancestor grant -- the ruleset stays live and the "deny" is simply inert.
/// Exclusion is therefore enumerate-and-skip: recursively grant `path`'s
/// entries unless a path in `exclude` matches exactly, in which case that
/// subtree is omitted entirely (recursing one level where an exclude is
/// nested, e.g. `.config/gh` grants `.config`'s other children individually).
fn grant_tree(ruleset: i32, path: &Path, access: u64, exclude: &[std::path::PathBuf]) -> std::io::Result<()> {
    if exclude.iter().any(|e| e == path) {
        return Ok(());
    }
    let has_excluded_descendant = exclude.iter().any(|e| e.starts_with(path) && e != path);
    if !has_excluded_descendant {
        add_path_rule(ruleset, path, access)?;
        return Ok(());
    }
    let Ok(entries) = std::fs::read_dir(path) else { return Ok(()) };
    for entry in entries.filter_map(|e| e.ok()) {
        grant_tree(ruleset, &entry.path(), access, exclude)?;
    }
    Ok(())
}

/// Build and enter the ruleset. Irrevocable: after `restrict_self` there is no
/// syscall that widens it, `PR_SET_NO_NEW_PRIVS` cannot be cleared, and
/// `unshare(CLONE_NEWUSER)` to uid 0 does not escape it (F-NEW-4, measured).
///
/// `exclude` is never enforced by a deny rule -- see `grant_tree`'s doc
/// comment for the measurements. That enumerate-and-skip mechanism is the
/// whole mechanism behind D5 Option B.
pub fn restrict(rw: &[std::path::PathBuf], ro: &[std::path::PathBuf], exclude: &[std::path::PathBuf])
    -> std::io::Result<()>
{
    let attr = RulesetAttr {
        handled_access_fs: FS_ALL,
        handled_access_net: NET_BIND_TCP | NET_CONNECT_TCP,
        scoped: SCOPE_ABSTRACT_UNIX_SOCKET | SCOPE_SIGNAL,
    };
    let ruleset = unsafe {
        libc::syscall(SYS_CREATE_RULESET, &attr as *const _, std::mem::size_of::<RulesetAttr>(), 0u32)
    };
    if ruleset < 0 {
        return Err(std::io::Error::last_os_error());
    }
    let ruleset = ruleset as i32;

    for p in rw { grant_tree(ruleset, p, FS_ALL, exclude)?; }
    for p in ro { grant_tree(ruleset, p, FS_RO, exclude)?; }

    let rc = unsafe { libc::syscall(SYS_RESTRICT_SELF, ruleset, 0u32) };
    unsafe { libc::close(ruleset) };
    if rc != 0 {
        return Err(std::io::Error::last_os_error());
    }
    Ok(())
}

```rust
//! The seccomp half of the composition.
//!
//! Two corrections from the independent spec lane are load-bearing here and
//! both fail *silently* if dropped:
//!
//! **C1 — stacking is not unconditionally monotonic.** A newer
//! `SECCOMP_RET_USER_NOTIF` filter can override earlier `USER_NOTIF`/`TRACE`
//! handling and continue a syscall. So every action below is terminal
//! (`Errno`), never `Trace` and never `Notify`, *and* the child is denied the
//! `seccomp` syscall and `prctl(PR_SET_SECCOMP)` outright.
//!
//! **C2 — register width.** Seccomp sees registers before the kernel truncates
//! arguments to their declared types, so `AF_UNIX | 0x1_0000_0000` compares
//! unequal to `AF_UNIX` under a 64-bit compare. Every comparison here is
//! `Dword`.
//!
//! **F-NEW-1 — io_uring.** `IORING_OP_SOCKET` reached `/run/docker.sock`
//! through this exact filter *and through bwrap*, first-party, on this kernel.
//! Denying the three ring syscalls closes it and costs nothing: git does not
//! use io_uring (measured — `status`, `commit`, `log` all rc=0).

use std::collections::BTreeMap;

use seccompiler::{
    SeccompAction, SeccompCmpArgLen, SeccompCmpOp, SeccompCondition, SeccompFilter, SeccompRule,
};

const PR_SET_SECCOMP: u64 = 22;

pub fn apply(net_allow: bool) -> std::io::Result<()> {
    let err = |e: seccompiler::Error| std::io::Error::other(format!("{e:?}"));
    let mut rules: BTreeMap<i64, Vec<SeccompRule>> = BTreeMap::new();

    // Unconditional terminal denials. An empty rule vector means "this syscall
    // always takes the match action".
    for nr in [
        libc::SYS_io_uring_setup,
        libc::SYS_io_uring_enter,
        libc::SYS_io_uring_register,
        libc::SYS_unshare,
        libc::SYS_setns,
        libc::SYS_seccomp,
        libc::SYS_socketpair,
        libc::SYS_mount,
        libc::SYS_pivot_root,
        libc::SYS_ptrace,
        libc::SYS_process_vm_readv,
        libc::SYS_process_vm_writev,
        libc::SYS_add_key,
        libc::SYS_keyctl,
        libc::SYS_request_key,
        libc::SYS_bpf,
        libc::SYS_perf_event_open,
        libc::SYS_userfaultfd,
        libc::SYS_open_by_handle_at,
    ] {
        rules.insert(nr, Vec::new());
    }

    // C1's second half: `prctl(PR_SET_SECCOMP, …)` is the other way to install
    // a filter, and it must be shut with the same terminal action.
    rules.insert(
        libc::SYS_prctl,
        vec![SeccompRule::new(vec![SeccompCondition::new(
            0,
            SeccompCmpArgLen::Dword,
            SeccompCmpOp::Eq,
            PR_SET_SECCOMP,
        )
        .map_err(err)?])
        .map_err(err)?],
    );

    // `socket(2)`: a default-deny allowlist over the family argument, not a
    // denylist (verdict §9.1 — "Move to default-deny allowlist. Omissions then
    // become visible compatibility failures instead of silent bypasses").
    // Strict tier: no family at all. Network tier: AF_INET/AF_INET6 only, so
    // AF_UNIX, AF_NETLINK, AF_PACKET and anything future are all denied.
    let socket_rules = if net_allow {
        vec![SeccompRule::new(vec![
            SeccompCondition::new(0, SeccompCmpArgLen::Dword, SeccompCmpOp::Ne, libc::AF_INET as u64)
                .map_err(err)?,
            SeccompCondition::new(0, SeccompCmpArgLen::Dword, SeccompCmpOp::Ne, libc::AF_INET6 as u64)
                .map_err(err)?,
        ])
        .map_err(err)?]
    } else {
        Vec::new()
    };
    rules.insert(libc::SYS_socket, socket_rules);

    let filter = SeccompFilter::new(
        rules,
        // Everything not named above runs. The boundary here is a *reduction*
        // of authority, not an allowlist of git's syscalls: a full allowlist
        // would break on the next git or glibc version and fail closed in a way
        // that reads as a Git-Vista bug.
        SeccompAction::Allow,
        SeccompAction::Errno(libc::EACCES as u32),
        std::env::consts::ARCH.try_into().map_err(err)?,
    )
    .map_err(err)?;

    let program: seccompiler::BpfProgram = filter.try_into().map_err(err)?;
    seccompiler::apply_filter(&program).map_err(err)?;
    Ok(())
}
```

## Task 5 — `command_async` / `command_sync`, the only non-literal spawners, and the `SandboxedCommand` chokepoint

**Deliverable:** `command_async`/`command_sync` — the two wrappers that take a `Policy`, a repo and args, and produce a ready-to-run `Command`; the shim path resolves without an env var in a normal install; nothing else in **production** code constructs a `Command` from a variable — `argv_boundary.rs`'s allowlist separately accounts for the handful of `#[cfg(test)]` fixture files (e.g. `shim_cli.rs`, `escape_suite.rs`) that legitimately do the same for test setup.

**Both wrappers already exist** (`crates/git-vista-server/src/sandbox/spawn.rs`). What this task actually adds is closing **C10 hazard #1**: today `command_async` returns a plain `tokio::process::Command`, and the crate's only production caller — `git_cmd.rs::sandboxed()` — calls `command_async(&policy, repo, &[])` with an **empty** arg slice, then the caller (`git_stdout_capped`) appends the real subcommand args afterward with `.args(args)`. Whatever `network_need`/policy classification `sandbox_argv` performed, it classified an argv that is not the one that executes. ```rust
//! The **only** two **production** places in this codebase that construct a
//! process `Command` from a program name that is not the string literal
//! `"git"`. Test code is a separate matter — `argv_boundary.rs` allowlists a
//! handful of `#[cfg(test)]` fixture files that also spawn the launcher for
//! test setup (e.g. Task 12's lifecycle battery), on the condition that they
//! route through this file's `command_sync`/`command_async` rather than
//! constructing their own `Command`.
//!
//! `argv_boundary`'s tripwire is keyed to that fact: this file is the single
//! blessed launcher site, and the form `Command::new(program)` is the single
//! blessed spawn form (INV-16, F7). Anything else — a second variable program,
//! a `PathBuf` program at another site, a helper taking a program name — fails
//! the contract job. That is deliberate: #144 built the tripwire to prove "no
//! shell, no arbitrary program", and this milestone must not spend that proof.

use std::ffi::OsStr;
use std::path::Path;

use super::{sandbox_argv, Policy};

fn argv_with_repo(policy: &Policy, repo: &Path, args: &[&OsStr]) -> Vec<std::ffi::OsString> {
    let mut argv = sandbox_argv(policy);
    argv.push(std::ffi::OsString::from("-C"));
    argv.push(repo.as_os_str().to_owned());
    argv.extend(args.iter().map(|a| (*a).to_owned()));
    argv
}

/// Build the async command without spawning. Split out so a caller that needs
/// the `Child` (the bounded-read primitive in `git_cmd`) configures stdio
/// itself, exactly as it does today.
pub(crate) fn command_async(policy: &Policy, repo: &Path, args: &[&OsStr]) -> tokio::process::Command {
    let argv = argv_with_repo(policy, repo, args);
    let program = argv[0].clone();
    let mut cmd = tokio::process::Command::new(program);
    cmd.args(&argv[1..]);
    cmd
}

pub(crate) fn command_sync(policy: &Policy, repo: &Path, args: &[&OsStr]) -> std::process::Command {
    let argv = argv_with_repo(policy, repo, args);
    let program = argv[0].clone();
    let mut cmd = std::process::Command::new(program);
    cmd.args(&argv[1..]);
    cmd
}

pub(crate) async fn spawn_git_async(policy: &Policy, repo: &Path, args: &[&OsStr])
    -> std::io::Result<std::process::Output>
{
    command_async(policy, repo, args).output().await
}

pub(crate) fn spawn_git_sync(policy: &Policy, repo: &Path, args: &[&OsStr])
    -> std::io::Result<std::process::Output>
{
    command_sync(policy, repo, args).output()
}

/// Convenience for the many callers that hold `&[&str]`.
pub(crate) fn os(args: &[&str]) -> Vec<&OsStr> {
    args.iter().map(|s| OsStr::new(*s)).collect()
}
```

/// The bootstrap policy. Resolution is a chicken-and-egg problem — the policy
/// needs the gitdir and finding the gitdir needs a policy — so this one grants
/// the *candidate* repo only, and nothing the repo names. If the gitfile points
/// elsewhere, `rev-parse` fails inside this sandbox, which is the same refusal
/// by a different route; the validation below turns it into a typed error
/// either way.
fn bootstrap_policy(repo: &Path) -> Policy {
    let home = std::env::var_os("HOME").map(PathBuf::from);
    let (mut rw, mut ro) = super::default_system_trees(Tier::Strict);
    rw.push(repo.to_path_buf());
    let mut excludes = Vec::new();
    if let Some(h) = &home {
        ro.push(h.clone());
        excludes.extend(super::secret_excludes_for_home(h));
    }
    Policy {
        tier: Tier::Strict,
        shim: super::shim::shim_path().expect("shim resolvable").to_path_buf(),
        bwrap: super::bwrap::bwrap_path().map(Path::to_path_buf),
        rw_trees: rw,
        ro_trees: ro,
        secret_excludes: excludes,
        net_ports: Vec::new(),
        // Resolution must never run a repository's hooks. `rev-parse` does not
        // fire hooks today; blocking them is cheap insurance against a future
        // git that does.
        hook_mode: HookMode::Blocked { empty_dir: super::no_hooks_dir() },
    }
}

pub(crate) fn resolve_and_validate(repo: &Path) -> Result<RepoPaths, RepoPathsError> {
    let args = super::spawn::os(&[
        "rev-parse",
        "--path-format=absolute",
        "--show-toplevel",
        "--git-dir",
        "--git-common-dir",
    ]);
    let out = super::spawn::spawn_git_sync(&bootstrap_policy(repo), repo, &args)
        .map_err(|e| RepoPathsError::NotARepository(e.to_string()))?;
    if !out.status.success() {
        return Err(RepoPathsError::NotARepository(
            String::from_utf8_lossy(&out.stderr).trim().to_string(),
        ));
    }
    let text = String::from_utf8_lossy(&out.stdout);
    let mut lines = text.lines();
    let mut take = |which: &'static str| -> Result<PathBuf, RepoPathsError> {
        let raw = lines
            .next()
            .ok_or_else(|| RepoPathsError::NotARepository(format!("rev-parse omitted {which}")))?;
        let p = PathBuf::from(raw.trim());
        // Canonicalise: the whole point is that the *resolved real* path is
        // checked, so a symlink or a `..` cannot walk out of a managed root.
        let real = std::fs::canonicalize(&p).map_err(|_| RepoPathsError::Unresolvable(p.clone()))?;
        if !crate::state::path_is_allowed(&real) {
            return Err(RepoPathsError::OutsideManagedRoot { which, path: real });
        }
        Ok(real)
    };
    let toplevel = take("toplevel")?;
    let git_dir = take("git_dir")?;
    let git_common_dir = take("git_common_dir")?;
    Ok(RepoPaths { toplevel, git_dir, git_common_dir })
}

/// The real policy builder. Every RW tree here is a *validated* path, which is
/// what makes F5 dead: no attacker-named absolute path can enter this list.
///
/// F4: a linked worktree's `--git-dir` lives under the **common** directory,
/// outside the worktree, so all three paths are granted — verified against
/// Landlock in the verdict, not against bwrap alone.
pub(crate) fn policy_for_repo(repo: &Path, tier: Tier) -> Result<Policy, RepoPathsError> {
    let paths = resolve_and_validate(repo)?;
    let mut p = bootstrap_policy(repo);
    p.tier = tier;
    // `bootstrap_policy` always builds `Strict` (Task 7's chicken-and-egg
    // resolution step); a non-Strict target tier must not inherit its `bwrap`
    // or lack its `net_ports` (row 19/23: never mutate a Strict policy across
    // tiers and leave a stale `bwrap`/empty `net_ports` behind).
    p.bwrap = if tier == Tier::Strict { p.bwrap } else { None };
    p.net_ports = if tier == Tier::Network { super::DEFAULT_GIT_PORTS.to_vec() } else { Vec::new() };
    p.hook_mode = HookMode::Run;
    let (rw_defaults, ro_defaults) = super::default_system_trees(tier);
    p.rw_trees = rw_defaults;
    p.rw_trees.extend([paths.toplevel, paths.git_dir, paths.git_common_dir]);
    p.rw_trees.sort();
    p.rw_trees.dedup();
    // `ro_trees` must be re-derived for `tier` as well, not left as
    // `bootstrap_policy` built them: that call hardcodes `Tier::Strict`, and
    // `default_system_trees(Strict)` adds `STRICT_ONLY_RO_TREES` (`/proc`).
    // The network tier has no mount namespace at all, so carrying that grant
    // across would grant the **host's** procfs — every other process on the
    // box, visible. `$HOME` is not part of `default_system_trees`, so it is
    // re-added here; the secret exclusion set already on `p.secret_excludes` is
    // what withholds `~/.ssh` & co. from it.
    p.ro_trees = ro_defaults;
    if let Some(home) = std::env::var_os("HOME").map(PathBuf::from) {
        p.ro_trees.push(home);
    }
    p.ro_trees.sort();
    p.ro_trees.dedup();
    Ok(p)
}
```

## Task 9 — The startup probe: capability vs escape, and the negative controls (INV-13, INV-14)

**Deliverable:** the server emits three named capability booleans **before** any escape check; a boot probe then launches the **composed** launcher (`sandbox_argv` + `sandbox::spawn::command_async`) against a throwaway repository whose `pre-commit` hook attempts one escape per layer and records what it managed to do into marker files; a host lacking userns reports `CapabilityAbsent` and never `FailOpen`; **a verdict other than `Contained` refuses to start the server** (INV-13 / Global Constraint 15); and four *distinct* degraded modes each leave exactly the check they remove open while every other check stays closed.

> **Read `design-docs/2026-07-29-escape-battery-anti-vacuity-contract.md` before writing this file, and read Tasks 11–13 for the mechanism.** This task was originally built on `probe_argv` plus a shim `--self-probe` JSON `ProbeReport`. **`probe_argv` is deleted (R10, and it is already gone from `sandbox/mod.rs`), and the `--self-probe` route never existed** — the shim's `parse()` has no such arm, its catch-all is `die(EXIT_ARGV, "unknown flag")`, `validate()` separately requires `program_args.first() == Some("git")`, and `bin/gv-sandbox/` contains only `main.rs` and `seccomp_filter.rs`. Global Constraint 2 (amended) names exactly one sanctioned composition route. So this task observes the way Tasks 11, 12 and 13 observe: **a hostile hook writes its one measured fact into a file under a tree the policy already grants read-write, read back after the composed launcher exits.** A missing or unparsable marker is a hard failure, never a silent pass.

> **What a boot probe proves, and what it does NOT.** It proves **the host can supply the tier** — that on *this* machine, right now, bwrap+Landlock+seccomp actually compose into a boundary a hook cannot cross. It is **not** a substitute for per-repository policy construction. Audit C12 established that the server is multi-repository and dynamic: boot registers configured-root children and persistent clones, `?repo=` addresses any catalog entry, rescan adds repositories after launch, and clone creates one at runtime — and `Policy` grants read-write to the **specific repo argument**. A design that treats one boot policy as covering every later operation is wrong, and "optimising away" per-operation `policy_for_repo` because the boot probe already ran would grant every repository the boot scratch repo's grants. Say this out loud in `probe.rs`'s module doc so a later reader cannot mistake the boot gate for a global policy.

> **Ordering is a requirement, not a preference.** Verdict §7.3 risk #3: *"CI silently validating only the degraded path. INV-13 is the guard, and it must land before the sandbox tests do, not after."* This task therefore precedes Tasks 10–14.

/// specific (see `Display`).
#[derive(Debug)] pub(crate) struct BootRefusal { pub verdict: ProbeVerdict }

/// One marker-file observation, keyed by check name. `String` values, not
/// booleans: the seccomp checks report the kernel's own numbers and the
/// procfs check reports a pid, and collapsing those to a bool is how a
/// "family of accepted values" gets reintroduced.
pub(crate) type Observation = std::collections::BTreeMap<String, String>;

/// Runs the composed launcher once against a throwaway hostile-hook repo and
/// returns what the hook managed to do. The single observer — the boot probe
/// and the negative controls both call this, so a control can never diverge
/// from the thing it is controlling.
pub(crate) async fn observe(policy: &Policy, repo: &Path) -> Result<Observation, LaunchFailed>;

/// `async` because it launches. Takes `caps` for the *log line only*: the
/// decision is made by execution (see the module doc's R4 note).
pub(crate) async fn verdict(caps: &Capabilities) -> ProbeVerdict;

/// `Ok(ProbeVerdict::Contained)` or refuse. There is no third outcome.
pub(crate) async fn run_at_startup() -> Result<ProbeVerdict, BootRefusal>;

// In `sandbox/mod.rs`, NOT here — it must sit beside `Policy` and `shim_argv`,
// and it must not exist at all in a release build (9.4).
#[cfg(feature = "sandbox-negative-controls")]
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum DegradeMode { LandlockOff, SeccompOff, IoUringAllowed, AllOff }
```

**Why `DegradeMode` lives on `Policy` and not in an env var or an argv splice.**
The old design spliced `--degrade <mode>` into a hand-built argv at
`argv.len() - 1`, relying on "`--self-probe` is always the last entry." With
that argv gone there is no trailing sentinel to splice against, and
hand-building an argv at all is now forbidden (Global Constraint 2: one route,
`sandbox_argv` + `command_async`). Three replacements were considered:

- **A positional splice at `argv.len() - 2`** (Global Constraint 4 guarantees
  the last two elements are `"--", "git"`). Works, but it still means a test
  building argv by hand and spawning it itself — a second composition route
  through the back door, and `command_async` appends `-C <repo> <args>` *after*
  `git`, so the test could not use the production seam anyway.
- **An env var the shim reads under `cfg`.** Zero changes to `Policy`,
  `shim_argv` or any literal — genuinely cheaper. Rejected: the shim is
  deliberately argv-only (`spawn.rs` does not touch env at all, by design), an
  env knob has no R10 round-trip to check, and if the `cfg` is ever mis-set the
  failure is silent. A flag with no `parse()` arm dies with exit 90, loudly —
  which is exactly what 9.5 asserts.
- **A `#[cfg]`-gated `Policy` field (chosen).** The negative control then drives
  the *real* production seam with no splicing at all, and R10's round-trip stays
  checkable in both directions (a builder emits it; `parse()` accepts it; both
  under the same `cfg`). The honest cost: under the feature, **every** `Policy {
  … }` literal in the crate must add `degrade: None`. That is three sites today
  (`policy_for_repo`, `shim_cli::workable`, `lifecycle::strict_policy_under_exemption`),
  the feature is compiled only by the sandbox CI job, and a missed site is a
  compile error in that job — never a silent hole. In a release build the field
  does not exist, so a release `Policy` is *structurally incapable* of
  representing a weakened shim. That is stronger than the old splice, which any
  code holding an argv could have performed at any time.

//! INV-13 and INV-14 — the two guards that stop this whole milestone from
//! validating only the degraded path.
//!
//! §9.4's emphasis on A11 is the design rule here: **"the startup probe must
//! test escape, not capability. Round 3's fatal error was verifying that a
//! cgroup could be created and killed, never that a process could not leave
//! one. A probe that asks 'is Landlock present?' repeats that mistake at a new
//! layer."** So `capabilities()` answers "could this host even try?" and
//! `verdict()` answers "did the composed launcher actually contain the child?"
//! — and the two answers are never merged into one boolean.

//! **This probe GATES BOOT.** INV-13 / Global Constraint 15: a host that
//! cannot supply the declared tier does not get a degraded server, it gets no
//! server. `run_at_startup` therefore returns `Result`, and `main` propagates
//! the refusal. Logging the verdict and returning — the shape this step used
//! to specify — is the degrade-and-carry-on posture C5 forbids one level up.
//!
//! **What this proves is about the HOST, not about any repository.** A green
//! verdict says "bwrap + Landlock + seccomp actually compose into a boundary on
//! this machine." It says nothing about which trees a given operation may
//! touch: `Policy` grants read-write to the **specific repo argument**, and the
//! server is multi-repository and dynamic (boot registers configured-root
//! children and persistent clones; `?repo=` addresses any catalog entry;
//! rescan adds repositories after launch; clone creates one at runtime —
//! audit C12). **Per-operation `policy_for_repo` is not made redundant by this
//! probe and must not be "optimised" away**; doing so would hand every
//! repository the boot scratch repo's grants.
//!
//! **Capability is established by EXECUTION, never by asking the host** (the
//! anti-vacuity contract's R4). `capabilities()` is read *first* — but only to
//! supply words for the log line and for `missing`. The deciding read is the
//! baseline leg: the cheapest real Strict operation there is, run through the
//! one production seam. A host that *reports* bwrap present can still fail to
//! launch it, and a query-based decision can never see that failure.
//!
//! **Observation is by marker file, not by a JSON self-probe.** `probe_argv`
//! and the shim's `--self-probe` mode are deleted/never-existed (R10); the
//! shim's `parse()` has no such arm and `validate()` refuses any argv whose
//! program is not literally `git`. So this file observes exactly the way
//! Tasks 11–13 observe: a hostile `pre-commit` hook writes its one measured
//! fact into a file under the scratch tree the policy already grants
//! read-write, read back after the composed launcher exits. **A missing or
//! unparsable marker is a hard failure, never a skip** — by the time a marker
//! is read, the baseline leg has already established capability, so an absent
//! marker means the hook did not run as expected, not that the host cannot try.

use std::path::{Path, PathBuf};

use super::spawn::command_async;
use super::{default_system_trees, secret_excludes_for_home, HookMode, Policy, Tier};

// The capability half lives in `sandbox::capabilities` and is NOT redeclared
// here (see the note at the head of this task). Re-exported under the name the
// rest of the plan's batteries import, so there is exactly one measurement.
pub(crate) use super::capabilities::{probe as capabilities, Capabilities};

/// **Only `Contained` permits boot.** The other two variants both refuse
/// (INV-13 / Global Constraint 15) — they are separate variants for the sake
/// of the *diagnosis*, not because the action differs. An operator reading
/// `capability_absent missing=["bwrap"]` installs bubblewrap; an operator
/// reading `fail_open failed=["fs_write_outside"]` has found a security bug in
/// git-vista. Collapsing them makes the second look like the first, and
/// mapping either to a "run anyway with hooks blocked" posture is the
/// best-effort downgrade C5 forbids.
#[derive(Debug, Clone, PartialEq, Eq)]
pub(crate) enum ProbeVerdict {
    /// Every check the boot probe made was contained, and its paired positive
    /// was granted in the same run.
    Contained,
    /// The composed launcher could not run here at all — the baseline leg did
    /// not exit 0. **Not** a hole: a different state entirely, and the one CI
    /// reaches on `ubuntu-latest` (F8: userns is clamped in 6 of 6 jobs).
    /// `missing` is named from `Capabilities` *after* the launch failed, so
    /// the words come from the fact and the decision comes from the execution.
    CapabilityAbsent { missing: Vec<&'static str> },
    /// The composed launcher ran, and a check that should have been closed was
    /// open — or a marker that should have been written was absent. This is a
    /// hole (or an unobservable probe, which must never be green), and the
    /// server refuses to start.
    FailOpen { failed_checks: Vec<String> },
}

// `capabilities()` is NOT written here — it is `sandbox::capabilities::probe()`,
// already built, and it already asks the kernel directly for the Landlock ABI
// (a version query needs no sandbox, and taking it from the shim would confuse
// "absent" with "the shim would not start"), already resolves `bwrap` only from
// `BWRAP_CANDIDATES` rather than by a PATH scan (row 5), and already does a
// three-sysctl userns check. The one thing to add there is:
//
//     seccomp_available: std::path::Path::new("/proc/sys/kernel/seccomp/actions_avail").exists(),
//
// measured, like every other field in that struct, as a fact and not a policy.

/// The escape half. Runs the **composed** launcher in `--self-probe` mode and
/// reads its truth table; it never installs a primitive itself.
pub(crate) fn verdict(caps: &Capabilities) -> ProbeVerdict {
    let mut missing = Vec::new();
    if !caps.landlock_meets_floor() { missing.push("landlock_abi>=6"); }
    if !caps.seccomp_available { missing.push("seccomp"); }
    if !caps.userns { missing.push("user_namespaces"); }
    if !caps.bwrap_present { missing.push("bwrap"); }
    if !missing.is_empty() {
        return ProbeVerdict::CapabilityAbsent { missing };
    }

    let scratch = match tempfile::tempdir() { Ok(d) => d, Err(_) => return ProbeVerdict::CapabilityAbsent { missing: vec!["scratch_dir"] } };
    let home = std::env::var_os("HOME").map(PathBuf::from);
    let (mut rw, mut ro) = super::default_system_trees(Tier::Strict);
    rw.push(scratch.path().to_path_buf());
    if let Some(h) = &home { ro.push(h.clone()); }
    let policy = Policy {
        tier: Tier::Strict,
        shim: match super::shim::shim_path() { Ok(p) => p.to_path_buf(), Err(_) => return ProbeVerdict::CapabilityAbsent { missing: vec!["shim_path"] } },
        bwrap: super::bwrap::bwrap_path().map(Path::to_path_buf),
        rw_trees: rw,
        ro_trees: ro,
        secret_excludes: home.iter().flat_map(|h| super::secret_excludes_for_home(h)).collect(),
        net_ports: Vec::new(),
        hook_mode: HookMode::Blocked { empty_dir: super::no_hooks_dir() },
    };

    let argv = match probe_argv(&policy) {
        Some(a) => a,
        None => return ProbeVerdict::CapabilityAbsent { missing: vec!["probe_argv"] },
    };
    let out = match std::process::Command::new(&argv[0]).args(&argv[1..]).output() {
        Ok(o) => o,
        Err(_) => return ProbeVerdict::CapabilityAbsent { missing: vec!["shim_launch"] },
    };
    if !out.status.success() {
        return ProbeVerdict::CapabilityAbsent { missing: vec!["shim_setup"] };
    }
    let report: serde_json::Value = match serde_json::from_slice(&out.stdout) {
        Ok(v) => v,
        Err(_) => return ProbeVerdict::CapabilityAbsent { missing: vec!["shim_report"] },
    };

    // The twelve checks that must be closed. A13's framing: an *escape* test,
    // not a capability test.
    let mut failed = Vec::new();
    for key in [
        "af_unix_socket", "af_unix_socketpair", "af_unix_high_bits",
        "af_inet_socket", "io_uring_setup", "unshare_user", "setns",
        "install_seccomp", "home_write", "dev_shm_write",
    ] {
        if report.get(key).and_then(|v| v.as_str()) == Some("OK") {
            failed.push(key.to_string());
        }
    }
    if report.get("open_fds").and_then(|v| v.as_array()).is_some_and(|a| a.len() > 3) {
        failed.push("open_fds".to_string());
    }
    if report.get("secret_reads").and_then(|v| v.as_array())
        .is_some_and(|a| a.iter().any(|p| p.get(1).and_then(|v| v.as_str()) == Some("OK")))
    {
        failed.push("secret_reads".to_string());
    }

    if failed.is_empty() { ProbeVerdict::Contained } else { ProbeVerdict::FailOpen { failed_checks: failed } }
}

/// Called once from `main`'s banner path. Prints the three named booleans
/// first, then the verdict — in that order, so a log that is cut short still
/// distinguishes the two.
pub(crate) fn run_at_startup() -> ProbeVerdict {
    let caps = capabilities();
    println!(
        "[sandbox] landlock_abi={} seccomp_available={} userns={} bwrap_present={}",
        caps.landlock_abi, caps.seccomp_available, caps.userns, caps.bwrap_present
    );
    let v = verdict(&caps);
    match &v {
        ProbeVerdict::Contained => println!("[sandbox] verdict=contained — hooks run under the strict tier"),
        ProbeVerdict::CapabilityAbsent { missing } =>
            println!("[sandbox] verdict=capability_absent missing={missing:?} — hooks BLOCKED (this is not a detected hole)"),
        ProbeVerdict::FailOpen { failed_checks } =>
            eprintln!("[sandbox] verdict=fail_open failed={failed_checks:?} — hooks BLOCKED"),
    }
    v
}

/// Runs the composed launcher's `--self-probe` mode with the negative
/// control's `--degrade <mode>` flag spliced in just before `--self-probe`,
/// and parses the resulting JSON into a plain string map. Only compiled with
/// `sandbox-negative-controls` (9.4) — a release shim has no `--degrade` flag
/// to splice in.
#[cfg(feature = "sandbox-negative-controls")]
pub(crate) fn degraded_probe(repo: &Path, mode: &str) -> std::collections::BTreeMap<String, String> {
    let policy = workable(Tier::Strict, repo, &shim());
    let mut argv = probe_argv(&policy).expect("Strict is always probeable");
    let cut = argv.len() - 1; // `--self-probe` is always the last entry.
    argv.insert(cut, std::ffi::OsString::from("--degrade"));
    argv.insert(cut + 1, std::ffi::OsString::from(mode));
    let out = Command::new(&argv[0]).args(&argv[1..]).output().expect("degraded probe runs");
    assert!(out.status.success(), "degraded probe `{mode}` exited {:?}: {}",
            out.status.code(), String::from_utf8_lossy(&out.stderr));
    let parsed: serde_json::Value = serde_json::from_slice(&out.stdout).expect("probe emits JSON");
    parsed.as_object().expect("probe report is a JSON object").iter()
        .map(|(k, v)| (k.clone(), v.as_str().map(str::to_string).unwrap_or_else(|| v.to_string())))
        .collect()
}

That contract was derived from audit C11 (0 PROVES, 4 VACUOUS, 1 UNCERTAIN) against the *escape* battery this task sits beside, and this battery has already failed on the identical fault: `blocked_hooks` — the one case in the old draft shaped like this one — was satisfied by `Tier::Unsandboxed + HookMode::Blocked`, no Landlock, seccomp or bwrap present at all. Sound as a functional test, worthless as containment evidence, and it was silently counted in a total it did not belong in.
>
> **Task 14's vacuity mode is the mirror image of the escape battery's.** The escape battery proves containment — the sandbox stops something; it is vacuous when a pass proves nothing was actually tried. This battery proves function — real git operations still work under the policy; it is vacuous when a pass would be **identical if the sandbox had never been applied at all**, because then it proves the operation works, not that it works *under the policy*. Every case below must be attributable to the policy actually being engaged, not merely to git working (which it always does, unsandboxed). See the "Contract binding" note after Interfaces for which rules bind unchanged, which are reinterpreted, and why this battery gets its own report file and census rather than sharing the escape battery's.

**Deliverable:** a husky-shaped hook runs **and gates** (both directions), `git commit` works with no repo-local identity, linked worktrees and submodules resolve, and the interpreter a hook resolves inside equals the one outside or startup says so.

### Files

- **Create:** `crates/git-vista-server/src/sandbox/compat.rs`
- **Create:** `docs/sandbox/compat-census.txt` — case-id census for this battery, kept separate from `docs/sandbox/escape-census.txt` (see "Contract binding" below for why).
- **Modify:** `crates/git-vista-server/src/sandbox/mod.rs` — `#[cfg(test)] mod compat;`
- **Modify:** `.github/workflows/ci.yml` — the gating job gains the same three report assertions R5 defines for the escape battery (file exists; case-id set equals the census in both directions; zero `capability-absent` records), pointed at `$GV_COMPAT_REPORT` / `docs/sandbox/compat-census.txt` instead of the escape battery's files.

### Interfaces

**Consumes:** `sandbox::escape_suite::hostile_hook_repo`, `sandbox::shim_cli::{shim, fixture}`, `sandbox::spawn::command_async`, `sandbox_argv`, `sandbox::repo_paths::resolve_and_validate`, and the Strict-policy constructor the escape battery's Strict cases use (name pinned by the Task 3/10 harness commit — this file must call the SAME one, never a second, compat-only builder). `shim_cli::launch` and `shim_cli::workable` are gone (Step 4) and must not appear here.

### Contract binding (design-docs/2026-07-29-escape-battery-anti-vacuity-contract.md)

**Rules that bind this file unchanged:** R1 (declarative structure: every case a `const CASE_X`, every `#[test]` body exactly `run_compat_case(&CASE_X)`, zero `assert*!`/`return`/`if`/`match`/`eprintln!` outside `mod harness`), R2 (exact named observation, never a predicate or negation), R5 (results to a report FILE, never stdout/stderr), R6 (every inside leg through `sandbox::spawn::command_async` composed from `sandbox_argv`, never `shim_cli::launch`), R7 (one pinned `production_env_profile()` — `HOME` stays real since the identity case's whole point is resolving `~/.gitconfig`; only extra `GIT_*` vars are restricted), R8 (expiring exemption — every case here uses `Tier::Strict`, which `policy_for_repo` cannot build until Step 8, so every case carries the same `NotProductionReachable` exemption the escape battery's Strict cases carry, and it expires the same way), R11 (self-binding rule registry).

**Rules reinterpreted for a positive claim:**
- **R3 (paired positive).** There is no exclude list under test here, so "sibling under the same granted tree" does not apply. What survives is "same policy, same run, same probe": the Strict policy each case runs under must be built by the identical constructor the escape battery's Strict cases use, never a second, more permissive, compat-only policy invented to make these tests pass — a compat case that only passes under a policy the escape battery doesn't also use proves nothing about the shipped configuration.
- **R4 (capability-by-execution), the load-bearing change.** For the escape battery R4 asks "did the mechanism actually run" so a denial can be attributed to it. For this battery the equivalent question is "was the mechanism actually engaged while this passed" — a pass under `Tier::Unsandboxed` is a pass in the English sense but proves nothing about the policy, which is exactly how `blocked_hooks` went wrong. Every case therefore pairs its exit-code/effect assertion with acceptance evidence (F): the probe's own `/proc/self/status`, `assert_eq!`'d for `Seccomp: 2` and `NoNewPrivs: 1` inside the sandboxed leg, in the same run — never a host-side `strict_available()`/`.exists()` check. This kernel self-report pairing is what the old `blocked_hooks` case needed and didn't have.
- **R9 (mutation matrix) does not bind this file the way it binds the escape battery, and no case here declares `dies_under`.** M1–M7 are all "remove or weaken a denial mechanism" mutants; weakening a denial mechanism cannot break a functional claim — it can only make one easier to satisfy. Forcing a `dies_under` entry here would manufacture a claim the mutation semantics can't support. What IS worth having, at near-zero marginal cost since the tree is already patched and rebuilt for R9: every case here also runs against M1–M7 and is required to stay PASS in every cell, as a regression-freedom sweep — if a security-weakening mutant breaks a compat case, that's a real finding worth surfacing, but it is not this battery's acceptance criterion.

**Report and census are separate from the escape battery's, not shared.** `run_compat_case` appends one line per case to `$GV_COMPAT_REPORT`: `GV-COMPAT case=<id> result=functional-ok|functional-broken|capability-absent:<missing> class=functional`. Kept separate rather than folded into `$GV_ESCAPE_REPORT`/`escape-census.txt` because the vocabulary doesn't fit: `result=escaped` is a security-breach word, and none of the six cases below makes a denial claim it could be true or false of. The one case in the old draft that DID make a denial claim — `hooks_blocked_mode_really_blocks`, the sandbox must block hook execution when `HookMode::Blocked` is configured — is exactly the one the contract's ordered-work item 5 already relocates into the escape mechanism (`hook_mode_suite.rs`, `class=functional`, `dies_under: [M6]`, under the escape census). That precedent is the reason a shared file is right for a hybrid containment-shaped case and wrong for a batch of pure functional ones: it shows the split was considered, not merely defaulted to.

/// The hook policy actually in force (M1.13b, #66 — ADR 0025 declared it,
/// the whole-sandbox ADR (`git-process-sandbox`, written in Task 18) makes it
/// real).
///
/// **This is now an enforced value, not only a disclosed one.** ADR 0025's
/// two-variant `Allow`/`Restricted` was a declaration with no code reading it;
/// these four name the tier the git-spawn chokepoint actually runs under.
/// The old wire strings still deserialize (`allow` → `Unsandboxed`,
/// `restricted` → `Strict`) so a stored older value is not a hard error, but
/// they are never emitted again.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum HookPolicy {
    /// Landlock + seccomp inside a pid/net/ipc namespace. Hooks run, and they
    /// cannot reach the network or a unix socket. This does not confine
    /// filesystem access to the repository: the policy also grants read-only
    /// system trees (`/usr`, `/bin`, `/lib`, `/lib64`, `/etc`, plus `/proc`
    /// under Strict), `$HOME` read-only minus the secret exclusion set, and a
    /// private `/dev` read-write. What Strict actually guarantees is that
    /// nothing is **written** outside the declared RW trees, and nothing is
    /// **read** outside the declared RO grants minus `secret_excludes`.
    #[serde(alias = "restricted")]
    Strict,
    /// Landlock + seccomp, no network namespace — the only policy under which
    /// `git push` can work (F3). Hooks run with `AF_INET` reachable.
    Network,
    /// No sandbox. Explicit, persisted, per-repository operator trust only, and
    /// it flies a permanent banner.
    #[serde(alias = "allow")]
    Unsandboxed,
    /// Hooks do not run at all: `core.hooksPath` points at an empty directory.
    /// The state the server drops to when the host cannot provide the declared
    /// minimum (`capability_absent`) or when the startup probe found a hole
    /// (`fail_open`).
    Blocked,
}

    /// anything other than `strict`."
    pub fn requires_banner(self) -> bool {

    /// value is unknown, assume hooks are not running rather than assume they

### Gaps found in this review, stated rather than silently dropped

1. **A12 is covered by a `sh` hook, not a `node` hook, and does not set `core.hooksPath`.** `compat::husky_pre_commit_runs_and_gates` writes `.git/hooks/pre-commit`; the matrix asks for the husky shape specifically — a repo-local `core.hooksPath` directory with a `node` hook. `sh` is guaranteed present in CI; `node` is not. **Resolution, corrected to the anti-vacuity contract (design-docs/2026-07-29-escape-battery-anti-vacuity-contract.md):** add `CASE_HUSKY_NODE_HOOKS_PATH: CompatCase` to Task 14's `compat.rs`, with a `harness::husky_node_hook` fixture that sets `core.hooksPath=.husky` and writes a `node` hook. Node absence is capability, not a loud print: `run_compat_case` records it the same way it records any other `CapabilityAbsent` (a report-file record, R4/R5), never an `eprintln!` — a `SKIPPED`/`[skip]` string on a passing test is swallowed by libtest and is byte-identical in CI whether or not the skip happened, which is the exact false-green channel the contract's skip-policy section documents. 2. **A15 is verified against a local bare repo, not over HTTPS through the global credential helper.** A test that pushes to GitHub cannot run in CI (no credentials, and it would mutate a real repo). **Resolution, accepted as a documented limitation rather than a task:** `dispatch::network_ops_are_not_in_netns` proves the tiering mechanism (network tier reaches a remote, strict tier does not), and F2 — *"Credential helper (`gh`) cannot read its own config under the same policy"* — is structurally closed by D5 Option B, since `~/.config/gh` is in the *secret exclusion set*. **That is a real, unresolved tension and it is flagged here, not papered over:** if `gh auth git-credential` needs to read `~/.config/gh` and that path is denied, `git push` over HTTPS **will fail** under the network tier. Task 8's `tier_for` returns `Tier::Network` for `PushBranch`, which removes the netns but not the exclusion. A manual, host-only verification step belongs in Task 17.3, and if it fails, the correct fix is a **narrowly scoped** exception — read-only access to `~/.config/gh` for the network tier only — recorded in ADR 0028 as a deliberate weakening with its reason, not a silent edit to the exclusion set.

3. **INV-9's exhaustiveness test leans on a hand-maintained `VARIANT_NAMES` constant.** A new `GitOperation` variant makes `tier_for`'s `match` fail to compile (good) but `VARIANT_NAMES` could be updated without classifying the variant thoughtfully. This is weaker than a derive macro would be. Accepted: adding a proc-macro dependency to `git-vista-protocol` for one constant is a worse trade, and the compile error is the real guard.

4. **`ProbeReport` grew field-by-field across Tasks 4, 11 and 12.** A worker executing tasks out of order will hit missing fields. Mitigation: Tasks 11.1 and 12.2 each state exactly which field to add. Execute Tasks 3→4→9→10→11→12 in order.

5. **The `hook_policy` wire change is not additive.** ADR 0025's `"allow"`/`"restricted"` stop being emitted. Serde aliases keep deserialization working, and server and SPA ship from one origin in one build, so no version bump is prescribed. Flagged because M1.02's contract rule is about *additive* fields and this is a value-domain change — a reviewer may reasonably want a protocol bump, and Task 16.8's golden-fixture diff is the place to make that call.
