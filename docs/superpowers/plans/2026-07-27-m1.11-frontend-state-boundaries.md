# M1.11 — Frontend State in Feature Boundaries: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every piece of frontend state exactly one owning feature module, backed by a
framework-free state core that is unit-tested on the host target, so that operation state
survives panel changes and no stale response can overwrite a newer generation.

**Architecture:** Each feature area gets a `core.rs` — plain Rust, no `leptos`, no `web-sys`,
compiled and tested on the host — plus a thin `signals.rs` wrapper that is
`#[cfg(target_arch = "wasm32")]`-gated and holds the core in an `RwSignal`. Transitions are
validate-then-commit: a rejected transition leaves the core byte-identical. This is the
pattern `history.rs`'s `LoadedHistory` already proved in M1.10; this plan generalizes it.

**Tech Stack:** Rust, Leptos 0.6 (`csr` feature only, `crates/git-vista/Cargo.toml:28`),
`wasm-bindgen-futures` (`spawn_local`), `gloo-net` for fetch, `web-sys` for `EventSource`.
Workspace crates: `git-vista` (frontend), `git-vista-protocol` (wire types).

**Source spec:** `docs/superpowers/specs/2026-07-27-m1.11-frontend-state-boundaries-design.md`
(decisions D1–D6). Read it before Task 1.

## Global Constraints

Every task's requirements implicitly include this section.

1. **No new test toolchain.** Do NOT add `wasm-bindgen-test`, a `.cargo/config.toml` test
   runner, a headless browser, or a CI job. All new tests are ordinary `#[test]` functions
   compiled on the **host** target and run by `cargo test --workspace`. (Decision D1, locked
   by the user 2026-07-27 with the words "Do not deviate".)
2. **Cores import no framework types.** A `core.rs` file must not `use leptos::…`,
   `use web_sys::…`, `use js_sys::…`, or `use wasm_bindgen…`. If a core needs a timestamp or
   randomness, it takes it as a parameter. This is what keeps it host-testable.
3. **Cores are NOT `#[cfg(target_arch = "wasm32")]`-gated.** Only `signals.rs` and view code
   are. A gated core would not compile on the host and its tests would never run — that is
   the exact trap `main.rs:41-75` sets today.
4. **Validate-then-commit.** Every fallible transition returns a typed outcome and leaves
   `self` unmodified on rejection. Model on `LoadedHistory::apply_page`
   (`crates/git-vista/src/history.rs:222-353`).
5. **No feature writes another feature's state.** Features raise intent to `operations`;
   `operations` publishes invalidation back. Cross-feature writes become calls into the
   owning module's public API.
6. **`status/` and `diff/` get a module and trait impl only — no behaviour.** They are M2
   (#68, #69). Do not write speculative state for them. (Decision D2.)
7. **ADR 0012 holds:** the app shell never scrolls; every scroll lives in an inner overflow
   container. Do not add page-level scrolling.
8. **Never touch host port 8080** — that is the user's live server. Live drives bind an
   ephemeral port inside `systemd-run --user -p PrivateNetwork=yes`.
9. **Git writes are the checkpointer's job.** A background checkpointer owns the index. Do
   not run `git add`, `commit`, `push`, `checkout`, `switch`, `reset`, `rebase`, or `stash`.
   Where a task says "Commit", that means: leave the tree in a green state and let the
   checkpointer take it, or hand the named landmark commit to the orchestrator.
10. **The gate is five checks, run verbatim** (`./dev gate`):
    ```
    cargo fmt --all -- --check
    cargo clippy --workspace --all-targets -- -D warnings
    cargo clippy -p git-vista --target wasm32-unknown-unknown --all-targets -- -D warnings
    cargo test --workspace
    trunk build
    ```
11. **Witness every named test before claiming it passes:**
    `cargo test -p git-vista -- --list | rg -x '<module>::tests::<name>: test'` then run it
    with `--exact`. A test that does not appear in `--list` does not exist.

```rust
//! The vocabulary every feature core shares.
//!
//! Deliberately framework-free: this module must never import `leptos`, `web_sys`,
//! `js_sys` or `wasm_bindgen`, so it compiles and is unit-tested on the host target by
//! the ordinary `cargo test --workspace` the gate already runs (M1.11, #64, decision D1).

use git_vista_protocol::plan::GenerationToken;

/// The outcome of a transition that was accepted.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Applied {
    /// State changed.
    Committed,
    /// The event was valid but a no-op — e.g. re-applying an already-recorded terminal.
    NoChange,
}

/// A feature's state core. Implementors must leave `self` untouched when `apply` errors.
pub trait FeatureCore {
    type Event;
    type Rejection;
    fn apply(&mut self, ev: Self::Event) -> Result<Applied, Self::Rejection>;
}

/// What a request was about, so an out-of-order response can be recognised.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum RequestTarget {
    Repository,
    Branch(String),
    Commit(String),
    Page(u64),
    Operation(String),
}

/// Identity carried by every async continuation that writes shared state.
///
/// Generalises M1.10's `PageRequestKey` (`crate::history`, `history.rs:490-508`) so the
/// same fencing protects the bare `spawn_local` sites in `menu.rs` and `picker.rs`, which
/// today write unconditionally and can race (design spec §3).
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct RequestKey {
    pub epoch: u64,
    pub generation: Option<GenerationToken>,
    pub target: RequestTarget,
}

impl RequestKey {
    /// True when this request may still commit its result.
    ///
    /// A request that carried no generation is fenced by epoch alone — that is the correct
    /// reading for endpoints that predate M1.10. A request that *did* carry one is stale
    /// the moment the live generation differs, including when the live side has none.
    pub fn is_current(&self, live_epoch: u64, live_generation: Option<&GenerationToken>) -> bool {
        if self.epoch != live_epoch {
            return false;
        }
        match (&self.generation, live_generation) {
            (None, _) => true,
            (Some(mine), Some(live)) => mine == live,
            (Some(_), None) => false,
        }
    }
}

/// Published by `operations` when a write settles; consumed by features holding server state.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Invalidate {
    pub generation: Option<GenerationToken>,
    pub scope: InvalidateScope,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum InvalidateScope {
    Everything,
    Graph,
    Status,
    Activity,
}
```

```rust
//! Repository-session state: who we are, how we are connected, and which UI mode is live.
//!
//! Framework-free (M1.11 D1). Before this module, these three facts lived in
//! `thread_local!`s inside `api.rs` (`:41` CSRF_TOKEN, `:58` UI_MODE, `:72` VIA_LAN) and
//! were read directly from six view sites, so nothing re-rendered when they changed
//! (design spec D6).

use crate::features::core_traits::{Applied, FeatureCore};

#[derive(Debug, Clone, Copy, Default, PartialEq, Eq)]
pub enum UiMode {
    #[default]
    Visualize,
    Active,
}

#[derive(Debug, Default, Clone, PartialEq, Eq)]
pub struct SessionCore {
    csrf: Option<String>,
    via_lan: bool,
    ui_mode: UiMode,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum SessionEvent {
    Established { csrf: String, via_lan: bool },
    /// The server told us what mode it believes is live (mirrors a loaded Frame).
    UiModeObserved(UiMode),
    /// The user picked a mode.
    UiModeSelected(UiMode),
    SignedOut,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SessionRejection {
    UiModeChangeWhileLan,
}

impl SessionCore {
    pub fn csrf_token(&self) -> Option<&str> {
        self.csrf.as_deref()
    }
    pub fn is_lan(&self) -> bool {
        self.via_lan
    }
    pub fn ui_mode(&self) -> UiMode {
        self.ui_mode
    }
}

impl FeatureCore for SessionCore {
    type Event = SessionEvent;
    type Rejection = SessionRejection;

    fn apply(&mut self, ev: SessionEvent) -> Result<Applied, SessionRejection> {
        match ev {
            SessionEvent::Established { csrf, via_lan } => {
                self.csrf = Some(csrf);
                self.via_lan = via_lan;
                Ok(Applied::Committed)
            }
            SessionEvent::UiModeObserved(m) => {
                if self.ui_mode == m {
                    return Ok(Applied::NoChange);
                }
                self.ui_mode = m;
                Ok(Applied::Committed)
            }
            SessionEvent::UiModeSelected(m) => {
                // Validate BEFORE mutating (global constraint 4).
                if self.via_lan {
                    return Err(SessionRejection::UiModeChangeWhileLan);
                }
                if self.ui_mode == m {
                    return Ok(Applied::NoChange);
                }
                self.ui_mode = m;
                Ok(Applied::Committed)
            }
            SessionEvent::SignedOut => {
                self.csrf = None;
                Ok(Applied::Committed)
            }
        }
    }
}
```

    use crate::features::core_traits::{RequestKey, RequestTarget};

    fn intent(epoch: u64, branch: &str) -> PendingIntent {
        PendingIntent {
            key: RequestKey {
                epoch,
                generation: None,
                target: RequestTarget::Branch(branch.to_string()),
            },
            kind: OperationKind::Delete { branch: branch.to_string() },

    #[test]
    fn a_slower_earlier_response_cannot_replace_a_newer_pending_intent() {
        // The menu.rs race (design spec §3): the user taps Merge, then Delete. Delete's
        // pre-check resolves first and opens the dialog. Merge's pre-check then resolves
        // and must NOT overwrite the dialog the user is looking at.
        let delete = intent(5, "other-branch");
        let stale_merge = intent(4, "feature");
        assert!(
            !latest_wins(Some(&delete), &stale_merge),
            "an intent from an older epoch must be dropped, not committed"
        );
    }

    #[test]
    fn a_newer_intent_replaces_an_older_pending_one() {
        let old = intent(4, "feature");
        let new = intent(5, "other-branch");
        assert!(latest_wins(Some(&old), &new));
    }

    #[test]
    fn the_first_intent_always_wins_when_nothing_is_pending() {
        assert!(latest_wins(None, &intent(1, "main")));
    }

    fn two_intents_from_the_same_epoch_resolve_to_the_incoming_one() {

/// A user intent that has been raised but whose pre-check has not yet resolved.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct PendingIntent {
    pub key: RequestKey,
    pub kind: OperationKind,
}

/// Whether `incoming` may replace `current`.
///
/// Fixes the `menu.rs` race (design spec §3): every branch item does a live
/// `fetch_head_branch()` pre-check and today writes `confirm_op` unconditionally in its
/// continuation (`menu.rs:352-363,378-389,422-433,540-548`), so responses commit in network
/// order rather than click order. Gating each continuation on this function makes the later
/// intent authoritative and drops the earlier straggler.
pub fn latest_wins(current: Option<&PendingIntent>, incoming: &PendingIntent) -> bool {
    match current {
        None => true,
        Some(cur) => incoming.key.epoch >= cur.key.epoch,
    }
}
